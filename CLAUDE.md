# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TechDigest is a batch pipeline that collects news from RSS feeds (technology + Brazilian politics), has an LLM write a summary and a multi-voice podcast script for each item, synthesizes the audio with Edge-TTS, and delivers each item to Telegram. It is meant to run unattended from a systemd timer. The user unit of the Ollama server and a target for test sessions are in `deploy/systemd/`; the unit of the pipeline and the timer are not in this repo yet, and the timer stays off until the owner says otherwise.

Everything in the codebase is written in Brazilian Portuguese: identifiers, comments, docstrings, log messages, LLM prompts and commit messages. Keep new code consistent with that.

## Commands

```bash
.venv/bin/pip install -e .                       # install (already installed editable in .venv, Python 3.14; requires >=3.11)
.venv/bin/techdigest                             # run the pipeline (same as: .venv/bin/python -m techdigest)
.venv/bin/python scripts/resumo_lotes.py         # per-run summary table parsed from today's log
.venv/bin/python scripts/resumo_lotes.py 07/10   # same, for a given day (DD/MM); --log <file> reads another log
.venv/bin/techdigest --simular <folder> --banco-origem <digest.db>   # a real run delivering to files, on a copy of the db
.venv/bin/python scripts/testar_agrupamento.py   # grouping diagnostic: no Telegram, digest.db opened read-only, LLM only with --etapa3
.venv/bin/python scripts/testar_episodio.py --amostra <file>   # generates a few episodes from a saved sample: LLM only, nothing delivered
.venv/bin/python scripts/checar_fidelidade.py    # checks those episodes against the source texts of their pautas: no LLM, no network
.venv/bin/python scripts/refazer_qa.py <folders> # reruns the current QA on recorded episodes: no LLM, no network
.venv/bin/pip install -e '.[dev]'                # dev extra (pytest)
.venv/bin/pytest                                 # tests
systemctl --user start techdigest-teste.target   # test session: brings up the Ollama of the user unit (stop it at the end)
```

- `scripts/testar_agrupamento.py` collects the feeds, extracts the texts (about a minute of network I/O), prints the "pautas" it would form and writes the top-scoring pairs to `data/agrupamento/pares_<timestamp>.csv`. Options: `--limiar`, `--peso-titulo`, `--max-candidatos`, `--incluir-vistos`. Every live collection returns different articles, so to compare thresholds on the same data use `--salvar-amostra` (also writes the extracted candidates to `data/agrupamento/amostra_<timestamp>.json`; since phase 4 each candidate also carries `feed`, the URL of the feed it came from, and `categorias`, the RSS categories of its entry, which older samples lack) and then `--amostra <file>`, which reruns the comparison on a saved sample with no network access. On a saved sample, `--rotulos <csv>` checks the result against hand-labelled pairs, and `--etapa3` asks the project's LLM to confirm each provisional pauta (one call per pauta, repeated with `--repeticoes N`) and writes `data/agrupamento/etapa3_<timestamp>.csv`. `--etapa3` runs the GPU checks of `ai/gpu.py` on the log of the Ollama unit (`OLLAMA_LOG`; `--log-ollama <file>` reads another one; see the Ollama bullet below). `--etapa3` takes the model lock (see Architecture), so it stops at once, saying who holds it, if a pipeline run, a simulation or another script is using the model, and its calls go through the machine brakes of `ai/maquina.py`, the same as the pipeline's. Start the test session (`systemctl --user start techdigest-teste.target`) before using it.
- `scripts/testar_episodio.py` rebuilds the final pautas of a saved sample (stages 1 to 3) and calls `Summarizer.process` for up to 4 multi-source pautas plus one single-source pauta as a control. `--repetir <relatorio>` reuses the pautas of an earlier report instead (same articles, order and relations, no stage 3), `--pautas "86+71;12"` adds pautas built from sample ids (the longest text is the principal), `--so-lados` runs only the side analysis of each pauta, and `--pasta <name>` picks the output folder under `data/agrupamento/` (default `episodios`). With `LLM_PROVIDER=ollama` it runs the GPU checks of `ai/gpu.py` on the log of the Ollama unit (`OLLAMA_LOG`, or `--log-ollama <file>`): it stops before loading the model if the NVIDIA driver does not answer or if the log shows that the server did not find the GPU, and after the first call it stops and unloads the model if the log shows the main model with no layer on the GPU. It writes each episode and a `relatorio_<timestamp>.json` (or `lados_<timestamp>.json`), rewritten after every pauta, prints memory, swap and temperatures before every LLM call, plus the memory of its own process and of the Ollama processes (resident, anonymous and swapped) and the RAM held by the compressed swap (zram), records which correction each episode needed and how much of each source went into it (which paragraphs entered each call that carries source text and why: lide, excerpt of side N, text order; and the paragraphs with an evidence excerpt that were left out, in the generation and in each revision), the answer and excerpt of each actor with what proves it carries the answer (`prova`) and the actors whose excerpt was refused, with the reason, for pautas with a dispute the analyst turn that repeats most words of each evidence excerpt (a word-overlap measure, not a rule), how many sentences of the texts mention the actors of each side, the thin sides and the word range applied to each analyst, the word budget of the pauta (`orcamento`, with the plan of the turns) and, for each character and the total, its target, range and how many words above the range it went (`alvo_por_personagem`, `alvo_do_total`; a diagnostic only), whether the script followed the plan (turns and average words of each character against the plan, and the order of the turns), who closes the episode (`plano_seguido.termina_com`; the QA does not check it) and, for each analyst, the side, the words, the target and the sentences of the side in the cut (`plano_seguido.analistas`; all diagnostics only), the thin-side analysts above 200 words (a diagnostic only, see the editorial rules), the roles, the number of turns and the analysts' sentences in the first person plural (a diagnostic only), and stops if available memory drops below `--min-memoria` GiB or if Ollama stops answering or unloads the model mid-run. With the CPU above `--max-cpu` (95 °C) before a call, it waits until the CPU is below `--retomar-cpu` (85 °C) and goes on; after 15 minutes of waiting it stops. The swap is only recorded: on this machine it fills up during generation with plenty of memory available. On the local model a generation call takes about 2 minutes. The script's own output goes to stdout only: redirect it to a file under `data/`, not `/tmp`. The memory, temperature, Ollama and GPU checks are the machine brakes of `ai/maquina.py` (the script only adds the per-call record), it takes the model lock before anything else, and its own stage 3 goes through the same brakes. Same test session as `--etapa3`.
- `scripts/checar_fidelidade.py` reads a `relatorio_<timestamp>.json` written by `testar_episodio.py` (the latest one by default, or `--relatorio <file>`), loads each episode and the articles of its pauta from the sample, and writes `data/agrupamento/fidelidade_<timestamp>.txt`. It lists the numbers, percentages and proper nouns of the title, `resumo_didatico`, `pontos_chave` and turns that appear in no text of the pauta (a number written out counts as its numeral), vague attributions ("especialistas afirmam") to a group the pauta never cites (the detection lives in `ai/atribuicoes.py` and the reading of numbers in `ai/numeros.py`, both also used by the QA), outlets missing from `fontes_citadas`, and, when `houve_divergencia` is true, fewer than two analysts and turns where Helena seems to take a side. As a diagnostic only, it also lists, when the pauta has two outlets or more, every sentence of the summary and the turns that attributes something to an outlet ("segundo o Jornal do Vale", "de acordo com", "conforme", or the outlet followed by a reporting verb such as "relata"), with the share of its content words found in the full text of the cited outlet and the highest share found in another outlet of the pauta; content words are compared by a root without plural, gender and verb endings, and the names of outlets, actors and characters and the words that every text of the pauta has do not count. A sentence where another outlet has the larger share is marked; the "strict rule" marks the ones with at least 5 counted words and another outlet 40 points or more above the cited one (on the four rounds of 12 to 14/10/2026 it marked 6 sentences, 5 of them wrong attributions checked in the texts; the thresholds were chosen looking at the first three, and it stays a diagnostic). In episodes with a dispute it shows, for each side, the analyst sentence that presents it (by the QA rule), the outlet it cites and that same measure. Open questions to a group (see the attribution rule below) are listed apart, outside the count, to show what that exemption lets through, and only this diagnostic, not the QA, also counts "Para os <grupo> <qualificador>, ..." at the start of a sentence as a vague attribution. It compares text, not meaning: a correct number used to say something else passes, and the Helena check is a word list. The equivalences and blind spots are in `COMO_LER`, printed at the top of every report. It is a diagnostic only: the pipeline does not use it, and of its checks only two are also QA rules: the attribution to a group the pauta never cites, and percentages and numbers from 10 up that no text of the pauta carries. Smaller numbers and proper nouns stay in the diagnostic only.
- `scripts/refazer_qa.py <folder or report>...` measures the effect of a change in the QA on the episodes already generated: for each episode of a `testar_episodio.py` report (a folder counts by its latest `relatorio_*.json`) it rebuilds the input of the QA (the outlets that entered the generation, the sides as the analysis left them, with the thin side recorded, the caveats, the full texts of the pauta from the sample, and the word budget: the one the report recorded or, in reports from before it, one recomputed from the words of the paragraphs that entered the generation; without that record, none, and the minimums of before apply), runs `qa.problemas_com_campo` on the recorded episode (for a rejected one, the version that came out of the correction) and compares with the recorded situation. It lists the episodes that change, with the reason, and, for those that become approved, what `checar_fidelidade.py` finds in them that the QA does not catch. It writes `data/agrupamento/refazer_qa_<timestamp>.txt`. Neither tool sees whether the side analysis chose the right question.
- Tests cover the word budget of `ai/orcamento.py` (total, shares, the plan of the turns closing the arithmetic of each target and starting and ending with Helena, the cap of 90 words per sentence of the side, the minimum always below the target) and its use by the block, the QA and the `Summarizer`, the pure functions in `processing/agrupamento.py`, the JSON parsing and the options each call sends in `ai/llm.py`, the input budget, the cut by relevance in every call that carries source text, the `process` flow and the four kinds of correction in `ai/summarizer.py`, the lide, the paragraphs of an excerpt and the cut in `ai/recorte.py`, the near-literal excerpt in `ai/recorte.py`, the validation of the side analysis, the answers per actor with their excerpts (literal or near-literal, and carrying the actor's answer: verb in the excerpt or the sentence, the sentence split at ";", quote, decision, marker; only with two named sides or more), the open question leading to the neutral side with any number of sides, the surname alone in the count of mentions (only for a person's name), the mention inside quotes that does not count, the "Sim" and "Não" of a two-sided dispute and its new attempt, the collectives of people and the institutions as groups, the thin sides, the caveats with their excerpts, the caveat whose group is an actor of a side, the two kinds of new attempt (the second one also for a refused excerpt), the texts that fit the call and the block in `ai/lados.py`, the GPU checks in `ai/gpu.py` (the main model read from the log, not the draft model), the source, title, analyst (the passive of a decision verb with the actor as agent included), analyst names from the block, role, caveat, attribution, number and word-range rules (with what is missing in each turn by the plan) in `ai/qa.py`, with the field each problem belongs to, the reading of numbers in `ai/numeros.py`, the names of the analysts by slot in `ai/elenco.py` and the voice of each one in `audio/tts.py`, together with the position verbs of `ai/verbos.py` (all through fake clients; no test calls an LLM), and the rules of `scripts/checar_fidelidade.py`, its attribution diagnostic included, and the rebuilt input and the comparison of `scripts/refazer_qa.py` (pytest finds the scripts through `pythonpath = ["scripts"]` in `pyproject.toml`), and what the code expects of the units in `deploy/systemd/` (the log of the Ollama unit is the default of `OLLAMA_LOG`), the model lock of `trava.py` (between processes too), the machine brakes of `ai/maquina.py`, the pipeline stopped by a brake or not started because of the lock, the lock and the brakes in the two scripts, the summary of `resumo_lotes.py` for those runs, the feed and the categories that the collection keeps for each article and the sample records (older samples still load), and the simulation: the folder, the read-only copy, the environment that beats the `.env`, the delivery to files, the refusal of `_post` and one whole simulation in a new process, with fake collection, extraction and generation and a `requests.post` that fails the test if called. `tests/conftest.py` runs before any import of the package: it turns off the `.env`, removes from the environment every variable named like a setting, fixes the `QA_*` limits at the values in force and points the database, the logs, the audio, the deliveries, the Ollama log and the model lock to a temporary folder, so the tests give the same result in any folder (the main one or a worktree), with or without a `.env`, and none of them writes to the production database or holds the real lock. The tests also run as a simulation (`TECHDIGEST_SIMULACAO`), so `_post` refuses to reach Telegram even if a test gets that far. There is no linter and no formatter configured. `requirements.txt` is empty and gitignored; dependencies live in `pyproject.toml`.
- **Running the pipeline has real side effects**: it calls the LLM, sends messages and audio to the configured Telegram chat, and marks URLs as seen in `data/digest.db`. The simulation below is real too, except for the delivery and the database: it calls the LLM and Edge-TTS and takes the model lock. Do not run either just to check a change; exercise the individual function instead (e.g. `collect_rss()`, `extract_full_text(url)`, `qa.problemas(result, veiculos, lados, ressalvas, textos)`).
- **Simulation** (`techdigest --simular <folder>`, `simulacao.py`): collection, extraction, LLM and TTS are real; the delivery goes to files in `<folder>/entregas` through the `arquivo` channel (`delivery/arquivo.py`: for each item the text exactly as Telegram would receive it, `_render_item` in HTML, the whole episode as JSON and the mp3, plus `entregas.txt` with the order and the end of the batch); the database is a copy, `<folder>/digest.db`, made with `--banco-origem` opened read-only (`mode=ro`) and SQLite's backup; the log and the audio stay in the folder, away from the log `resumo_lotes.py` reads by default. A new folder must not exist or be empty and needs `--banco-origem`; a folder of an earlier simulation (marked by `.simulacao`) goes on with its own database, which is how a second run is simulated; any other folder is refused, so a simulation never writes to a database that is not its own. `simulacao.preparar()` puts the folder's paths, `DELIVERY_CHANNEL=arquivo`, empty `TELEGRAM_TOKEN` and `TELEGRAM_CHAT_ID` and `TECHDIGEST_SIMULACAO` in the environment before anything of the package reads the configuration (the environment beats the `.env` in pydantic-settings), which is why `main.py` imports the package inside `main()` and `simulacao.py` uses only the standard library. No path of the simulation calls the Telegram API: the channel is `arquivo`, the token is empty, and `delivery/telegram._post` refuses to run with `TECHDIGEST_SIMULACAO` set; the `arquivo` channel in turn refuses to run outside a simulation, where it would mark items as seen in the production database without delivering them. `--sem-audio` skips the TTS, for work simulations only; the simulation that clears the merge has audio. Put the folders under `data/simulacoes/`.
- Always enter through `techdigest.main` (the console script or `python -m techdigest`). `python -m techdigest.pipeline` skips `setup_logging()`, so nothing reaches the log file.
- System requirements outside pip: `ffmpeg`/`ffprobe` on PATH (audio concat and duration), network access for Edge-TTS, and an Ollama server at `OLLAMA_HOST` when `LLM_PROVIDER=ollama`.
- The Ollama server runs as the user unit `deploy/systemd/ollama.service`, not by hand. The owner installs it (copied into `~/.config/systemd/user/`, with `~/.local/state/techdigest/` created beforehand). It has `StopWhenUnneeded=yes`, so it stays up only while an active unit needs it, and a `systemctl --user start ollama.service` by hand stops it right away; for test rounds that unit is `techdigest-teste.target` (`BindsTo=` the server, so the session falls if the server falls). The unit does not start without the NVIDIA driver (`ExecStartPre=nvidia-smi -L`) and only becomes active once the server has logged its `inference compute` line with `library=CUDA`; otherwise it fails and the server is stopped before any model is loaded. So when `systemctl --user start` returns, the server answers and the log already has the device. Its output goes to `OLLAMA_LOG` (default `~/.local/state/techdigest/ollama_serve.log`, the `%S/techdigest` of the user units, outside both project folders): emptied by `ExecStartPre` at each start and written in append mode, because with `truncate:` every command of the unit, `ExecStartPost` included, empties the file again; and systemd opens it before it would create a `StateDirectory=`, which is why the folder comes from the installation. The unit sets `LLAMA_ARG_CACHE_RAM=0`. The variable reaches the `llama-server` process that runs the model and turns off its prompt cache (the log then says "prompt cache is disabled"). The model uses sliding window attention (SWA), so the cache is never reused between calls, and with the default of 8192 MiB the anonymous memory of `llama-server` kept growing during a run (from 1.1 to 2.0 GB in five episodes, and available memory dropped by about 2 GB); with the cache off it stays flat, at the same speed. The GPU checks of the scripts read the same `inference compute` line in that log, and refuse a log of another start of the server, which is what a server started by hand gets. Without the GPU, Ollama loads the whole model into RAM and on this machine the memory runs out during the load; `ai/gpu.py` holds the checks (`conferir_antes_de_carregar`, `modelo_na_gpu`), used by the pipeline and the scripts through the machine brakes (`ai/maquina.py`). After the load, `/api/ps` only confirms that the model is loaded: the size it reports (1.2 GiB, 0.9 of it on the GPU) does not describe this model. The check reads in the log the last load of the main model, the `--model` file of the line `loading model via llama-server`: its `offloaded N/M layers to GPU` (27/31 on this machine, with 2.6 GiB on the GPU and 15.9 GiB mapped in RAM, the MoE weights staying in RAM) and its buffer sizes. The lines after `loading draft model` belong to the draft model, which fits entirely on the GPU (5/5) and would let a main model entirely on the CPU pass. With no layer of the main model on the GPU, or no load in the log, it unloads the model and stops. It also reports the video memory of `llama-server` from `nvidia-smi`, as information.

## Configuration

- All settings are fields of `Settings` in `src/techdigest/config.py` (pydantic-settings), read from `.env` at the repo root. The env var name is the field name in upper case (`max_news` → `MAX_NEWS`).
- Reading `.env` is denied in `.claude/settings.json`. Use `config.py` as the reference for which keys exist and their defaults, and ask the user for actual values. The feed list in particular comes from `RSS_FEEDS` (comma-separated) in `.env`; the defaults in code are not what runs in practice.
- Every module creates its own `settings = Settings()` at import time, and `ai/qa.py` copies the `QA_*` limits into module constants at import. Settings therefore cannot be overridden in one place at runtime; an override has to be in the environment before the modules are imported.
- `LLM_PROVIDER=ollama` selects `OllamaProvider`; any other value selects `OpenAIProvider`, which covers every OpenAI-compatible endpoint (Groq, OpenRouter) through `OPENAI_BASE_URL`.

## Editorial rules

The rules below are the ones in force today. They are referred to by name, not by number: the comments in the code mention "regra 1", "regras 2, 3 e 6" and similar, but the numbered list is not in the repository and those numbers could not be matched to specific rules. Do not infer a number's meaning from the code; ask the owner.

Two criteria decide how these rules change. A verb that presents the statement as true never enters the list of position verbs ("constatar", "revelar", "reconhecer", "admitir"): in a pauta with a dispute it takes a side. A new verb that passes that criterion goes into the single list of `ai/verbos.py`, and relaxing the analysts rule with it is a relaxation; separate lists only for a verb that serves one rule and not the other (the decision verbs are the case: they prove an actor's answer in the side analysis and, in the QA, count only in the passive with the actor as agent, but attribute no position). And a rule that relaxes the QA goes in directly, while a new rule that rejects goes first through a diagnostic (`scripts/checar_fidelidade.py`, with `scripts/refazer_qa.py` to see its effect on the recorded episodes) and only then into `ai/qa.py`; extending the closed list of an existing rule that rejects counts as a new rule.

**Verified by code.** An item that violates one of these gets one correction (see "The corrections" below) and, if it still violates, is skipped (`ai/qa.py`):
- Summary with 7 to 10 sentences (`resumo_didatico`). The prompts ask for 8 to 9, plus one closing sentence about the debate when `houve_divergencia` is true, to leave a margin.
- Words per character and in total follow the word budget of the pauta (`ai/orcamento.py`, see "The word budget" below). The maximums do not change: 650 per character (`QA_MAX_POR_PERSONAGEM`, the value in force since it was set in `.env`; the default of `config.py` since phase 4) and 1300 in total (`QA_MAX_TOTAL`). The minimum of each character is 60% of the target the block asks of it, and the minimum of the total 60% of the total target, never above the minimums of before: `QA_MIN_POR_PERSONAGEM` (240), `QA_MIN_LADO_FINO` (120) for the analyst of a thin side, `QA_MIN_HELENA_COM_DEBATE` (180) for Helena with two analysts or more, and `QA_MIN_TOTAL` (600). So the minimum is always below the target the block asks for, and the difference is a margin, as with the sentences of the summary. Without a budget (`orc=None`), the minimums of before apply. Below the minimum, the message also says what is missing in each turn by the plan of the block (`qa.o_que_falta`, third decision of 24/10/2026): with the number of turns of the plan, how many words to add to each ("4 falas de uns 49 palavras; o plano pede 4 falas de uns 90: acrescente uns 40 palavras a cada fala, com o que os textos trazem"); with another number, how many words are missing for the target; an analyst with no side has no plan, only the missing words. How far each character is from its target, and the cap of 200 of the thin-side analyst (`QA_MAX_LADO_FINO`), are diagnostics of `scripts/testar_episodio.py`, not QA rules: a cap in the QA is for the owner to decide after the regression. The fraction was 75% until the fourth decision of 24/10/2026, which lowered it to 60% (`orcamento.FRACAO_DO_MINIMO`), a relaxation: since 23/10 the analysts stay between 66% and 73% of their target, and neither the plan of the turns nor the message per turn made them write more; the analyst with full material (target 430) already passed with 240, 56% of the target, and the fraction gives the others the same slack. The plan still asks for the whole target. Measured before: at 60% the regression of 23/10 would have had 12 of 20 approved (4 at 75%), and the third short run of 24/10 6 of 8 (3 at 75%; `data/agrupamento/correcoes_20261024/fracao_do_minimo.py`).
- Every speaking character is declared in the cast, and every declared character speaks.
- Source text with at least 1200 characters, so headlines alone never become an episode (`pipeline.py`).
- Article published no more than 7 days ago (`MAX_IDADE_DIAS`).
- When an episode has two or more outlets as sources, every one of them appears in `fontes_citadas` (accent- and case-insensitive, one name may be contained in the other, compared by whole words). Single-source episodes are not affected, and the pipeline only produces single-source episodes today.
- Title without percentages or proportions (`proporcoes_no_titulo`): no percentages, no "x vezes" (nor "dobro", "triplo", "quádruplo") and no proportions ("metade", "um terço", "três em cada quatro", "6 de 11", "a cada 9 horas", "maioria", "minoria", "maior parte", "grande parte"). An absolute quantity passes, in digits or written out, with or without "quase", "mais de" and similar ("12 mortos", "doze mortos", "mais de 100 mortos"), and so do years, ordinals and names that carry a digit ("Eleições 2026", "1º turno", "BR-101").
- Analysts per side (`problemas_dos_analistas`), for every episode. The side analysis (see "The side analysis" below) says how many sides the pauta has, from 1 to 3. The episode must have exactly one analyst per side (Helena does not count), and `houve_divergencia` must be true if and only if there are two sides or more. With two sides or more there must be a one-to-one match between analysts and sides in which each analyst has one sentence that cites an outlet of that side, uses a position verb and names an actor that only that side has. Since 24/10/2026 (third decision) a sentence that cites an outlet of the side and has a decision verb in the passive with that actor as agent also presents it (`verbos.agentes_da_decisao`: a participle of `FORMAS_DE_DECISAO`, the same list the side analysis uses, followed within 3 words by "por", "pelo", "pela", "pelos" or "pelas"; the agent runs to the next verb, conjunction or semicolon, so with two agents only the first counts), as in "segundo a Agência Brasil, a suspensão do canal foi determinada por decisão do presidente do TSE, Kassio Nunes Marques" (the A63 of 24/10, whose text only carries Kassio that way). Measured on the 44 recorded episodes with two sides or more (`data/agrupamento/correcoes_20261024c/medir_passiva.py`): only that sentence starts to count. An actor counts as named when the sentence has more than half of the words of its name that no actor of another side uses, so "Duarte Valença" stands for "Teodoro Duarte Valença", while a name of one or two words must appear in full. The position verbs are a closed list of inflected forms in `ai/verbos.py` (27 verbs, among them "informar", "concluir", "dizer" and "declarar", the verbs of a technical body or a spokesperson, and "classificar" and "ressaltar", added on 23/10/2026; third person present, preterite and imperfect, singular and plural, the gerund and the infinitive), compared as whole words and accent-sensitive, so "negócio" is not "nega" and "crítica" is not "critica". The compound preterite counts as a pair, an auxiliary (tem, têm, tinha, tinham, teria, teriam, havia, haviam) followed by the participle ("havia classificado", "tinha dito"): the participle alone does not count, since "dito" and "pedido" are also nouns. "Considerar", "justificar", "pedir" and "chamar" stayed out (owner's decision of 23/10/2026).
- Caveats (`problemas_das_ressalvas`). Each caveat of the pauta must appear in a turn of Helena that contains a question mark and has one sentence that cites an outlet of the caveat, names one of its groups and uses a position verb ("Segundo o Jornal do Vale, economistas alertam que... Como você vê isso?"). The group counts by its main word (the first one that is not an article, a particle or a quantifier), in any number or gender, so "pesquisadora" stands for "pesquisadores"; a form of a position verb is not a group term ("critica" is not "críticos"). The side analysis no longer produces a caveat with no group (it is an invalid answer); the QA function still accepts one, which then only needs the outlet, the verb and the question mark. The rule checks the form, not whether Helena evaluates the caveat.
- No attribution to a group that the pauta never cites (`problemas_das_atribuicoes`). The title, the summary, the key points and the turns may not attribute anything to an unnamed group ("para os analistas, ...", "especialistas afirmam", "segundo as análises") unless some text of the pauta (title or full text of any of its articles) has a word of the same family. The groups, the attribution markers and the verbs are closed lists in `ai/atribuicoes.py`; "para os <grupo>" only counts at the start of a clause and followed by a comma, and a group preceded by "nossos", "dois" and similar is the cast of the episode, not a source. An open question is not an attribution: a sentence that ends in "?" and has an interrogative word (o que, como, qual, quais, por que, quem, onde, quando) before the group ("O que os especialistas dizem sobre isso?"); a question that carries a statement ("Os especialistas dizem que..., não é?") still counts. The verbs after the group are the plurals of the first 21 position verbs plus a few others; the list does not follow the position verbs added later, since a new verb there would make the rule reject more.
- Numbers come from the pauta (`problemas_dos_numeros`). Every percentage, and every other number from 10 up, in digits or written out, in the title, the summary, the key points and the turns must be in some text of the pauta (title or full text of any of its articles). A percentage only matches a percentage, and a decimal said with "vírgula" is read as one number ("quarenta e dois vírgula cinco por cento" is 42,5%). Rounding follows `numeros.tem_fonte`: with "cerca de" or "aproximadamente" the number may be up to 5% away from one of the source; with "quase" the source must be below what is said and with "mais de" above it, also within 5%; with no qualifier only the integer that rounds or truncates a decimal of the source passes (12,6 may be said as 12 or 13). The same holds in the scale in which the episode says the number: said in thousands, millions or billions, it may round or truncate the source value in that scale, whatever the form the source writes it in ("245 milhões" or "246 milhões" for R$ 245,5 milhões or R$ 245.500.000), as long as the source number in that scale is 10 or more, so "3,6 bilhões" is never "três bilhões" (`Numero.escala`, `MENOR_NUMERO_NA_ESCALA`). "E meio" after milhão, bilhão or trilhão adds half the scale ("dois milhões e meio" is 2.500.000); not after mil or units ("dez e meia" is a time). Smaller numbers stay in the diagnostic. A known gap of the reading, left for the diagnostic because fixing it would make the rule reject more: "três vírgula seis bilhões" is read as 3,6, without the scale.
- The role of an analyst (`problemas_dos_papeis`). The field `papel` of a character other than Helena may not carry the name of an actor of the sides ("analista da Construtora Alfa").
- The names of the analysts (`problemas_dos_nomes`, fourth decision of 24/10/2026). The code gives them (`ai/elenco.py`) and the block of sides says them, so every analyst who speaks in the script must have one of the names the block gives (compared without accent or case, titles included: "Dr. Otávio" is not "Otávio"); the name is checked, not the side. The problem belongs to the cast, so it asks for the full revision, which may rename the analyst to the name of the block (`PROMPT_REVISOR`); the script revision keeps the names. Until the third decision the model chose the names, and the QA only refused the name or first name of an actor (the N86 called its analyst "Bruno Silva", the columnist who is the source); the sentence in the prompt that forbade it made all 12 analysts of the third short run come out with function names ("Analista de Política", "Analista Jurídico"), against none in 140 before, and it was dropped.

**Requested in the prompt only.** The model is instructed to follow these, but nothing checks them (`ai/prompt.py`):
- Use only information from the sources; do not invent data or quotes.
- Who says what (`## QUEM DIZ O QUÊ` in `PROMPT_SISTEMA`, a short version in `_REGRAS_DO_ROTEIRO`): accusation, criticism, opinion, evaluation and forecast are always attributed to whoever makes them, in the whole episode, even with a single side and no answer; a caveat of the outlet itself ("a estimativa é da associação, não de um levantamento independente") is kept, attributed to the outlet; the outlet's own analysis is attributed to the outlet, never to an actor or stated as fact; Helena, the analysts and `por_que_importa` add no evaluation, motive, consequence, forecast or argument the texts do not carry; with little material the target of the block is already smaller, and they meet it with what the texts carry, with no new argument (the "say less" of 23/10 was dropped on 24/10, since it contradicted the instruction to expand to the target); Helena builds no choices, dilemmas or contrasts the texts do not make (comparing two proposals is not putting the listener before a choice).
- Short, attention-grabbing title without sensationalism, derived from `resumo_didatico`: it states nothing the summary does not (only the absence of percentages and proportions is checked by code). The title names the actors as the sources name them, without turning a person into the institution or the state.
- 2 to 5 self-contained key points.
- "Why it matters" section with 1 to 3 sentences, with the impact the texts carry: no consequence or forecast they do not make.
- Helena is fixed as the presenter and only moderates: she asks, sums up and hands over, without taking a position.
- The plan of the turns that the block gives (see "The word budget"): how many turns each character has, of what size and in what order, starting and ending with Helena (since 24/10/2026; before, a single number of turns of 70 to 80 words for everyone, which gave Helena half of the words). Before answering, the model counts the words of each turn and expands the turns to the size of the plan, so that each character reaches its target, with what the texts carry, with no new argument (`PROMPT_SISTEMA`). Both revisions get the same block and keep the plan: they fix what the QA pointed out without shortening the turns (`_REGRAS_DO_ROTEIRO` and the two revision prompts; in the A63 and the N13 of 24/10 the revision had taken the script below the minimum).
- Helena opens, moderates and closes the episode. In the closing she recaps the facts and the positions, each attributed to whoever holds it, and says goodbye; she only speaks of what remains open when the texts say what remains open, and draws no conclusion the texts do not draw ("fica claro que...", quoted in the prompt as what not to do) (`PROMPT_SISTEMA` and `_REGRAS_DO_ROTEIRO`, second decision of 24/10: in the short run of that day, "what the texts say remains open" produced unsupported claims in 3 closings of 8). Who closes is not checked by the QA: `scripts/testar_episodio.py` records it as a diagnostic (episodes ending with an analyst: 6 of 20 on 17/10, 1 of 20 on 23/10, 2 of 8 on 24/10).
- Written to be spoken: no markdown, URLs or lists.
- Cite outlets by name.
- The question of the block is an internal guide: Helena presents it once, at the opening, in natural words, without repeating it literally and without turning the positions of the sides into questions attributed to the actors. The analysts present the positions.
- With two sides or more, each analyst answers for one side and sustains its position with the arguments of the sources: no criticism of the own position, no endorsement of the other side, no judgement of his own. He speaks in the third person ("a construtora sustenta..."), never as a spokesperson ("nós", "não podemos aceitar"), and the analyst of a thin side does not expand beyond what the sources carry (the prompts no longer give him a fixed range: his target comes from the budget). With a single side the analyst explains the position and answers the caveats with what the sources say, without advocating.
- In `personagens`, the analysts take the names the block gives (checked by code) and the role goes in `papel`, which states a speciality and no tie to an actor (the tie is checked by code).
- Helena brings each caveat as an attributed question without evaluating it, followed by an open question that does not rephrase the alert in her own words (only the form is checked by code). The code checks the form of the attribution (outlet, position verb and actor in one sentence), not whether it is faithful to the texts, nor Helena's neutrality.
- The episode neither invents a side, actor or position that the sources do not carry nor omits a side or a caveat of the block.
- With several sources, `resumo_didatico` carries the consensus. The sentence announcing the debate only appears, as an extra closing sentence, when `houve_divergencia` is true.

**Other editorial principles in the code:**
- "Boletim duplo": feeds are interleaved so `MAX_NEWS` is not consumed by the first feeds alone, since TechDigest and PulsoBR share each batch (`collectors/rss.py`).

## Architecture

`main.main()` reads the arguments (before importing anything that reads the configuration, see the simulation), sets up logging and calls `pipeline.run()`, which takes the model lock and then loops over the articles in `pipeline._executar()`. The model lock (`trava.py`) is a non-blocking exclusive `flock` on a fixed path outside both project folders, `~/.local/state/techdigest/modelo.lock` (next to the Ollama log, never from `.env`, so the main folder, a worktree and a simulation share it), taken by everything that calls the model: the pipeline, the simulation, `testar_episodio.py` and `testar_agrupamento.py --etapa3`. The holder writes its command, PID, start time and folder in the file; a run that finds it busy logs `Execução não começou: ...` with that text and exits with status 1. Before the loop, `_executar()` wraps the provider in the machine brakes (`ai/maquina.ProviderVigiado`) and checks the GPU, before collecting anything:

1. `collectors/rss.collect_rss()` downloads each feed, filters by age (`MAX_IDADE_DIAS`) before applying `MAX_POR_FEED`, and **interleaves** the feeds so `MAX_NEWS` is not consumed by the first feeds only. Each `Article` keeps the URL of its feed (`feed`, the first one in the interleaved order when a link is in two feeds) and the categories of its entry (`categorias`), for the filter of phase 4.
2. `storage/dedup.SeenStore` (SQLite table `seen`, keyed by SHA-256 of the URL) skips items already delivered.
3. `processing/extractor.extract_full_text()` fetches the article body with trafilatura. Google News links are first resolved to the publisher URL with `googlenewsdecoder`; trafilatura is never run against a google.com URL (it would return the cookie-consent page). Items with less than `MIN_TEXTO_CHARS` of text are discarded.
4. `ai/summarizer.Summarizer.process()` asks the LLM for the question in dispute and the sides of the pauta, on the whole texts (`ai/lados.py`, one call with `PROMPT_LADOS`, repeated once if the answer is not valid or lacks the entry of an actor), cuts each text by relevance to a size budget (see below), calls the provider with `PROMPT_SISTEMA` and the input that carries the sides, runs the deterministic checks in `ai/qa.py`, and on failure makes **one** correction, of the kind the problems ask for (see "The corrections" below; only the title correction may take a second call). If the corrected episode still fails it raises `QAReprovado`. Every item therefore costs two LLM calls, plus one when the side analysis has to be retried and one or two with a correction (two when the title correction is repeated): five in the worst case.
5. `audio/tts.gerar_podcast()` synthesizes one mp3 per dialogue turn, inserts silences with ffmpeg and concatenates into `data/audio/<slug>.mp3`.
6. `delivery.deliver_item()` sends the text and then the audio to Telegram, and only after that does the pipeline call `seen.mark_seen()`.

Invariants worth preserving:

- **Deliver first, mark seen after.** An interrupted run neither loses nor repeats a delivered item, and anything not delivered comes back on the next run. This includes QA rejections (retried next run) and the case where the text was sent but the audio upload failed (`AudioNaoEnviado`): the item is not marked seen, so the next run sends it again in full.
- **One bad item never kills the run.** Generation errors are caught per item and logged. Only `MAX_FALHAS_ENTREGA` consecutive delivery failures abort the run, by raising, which makes `main` exit with status 1 for systemd.
- **A machine brake stops the whole run.** Memory, temperature and GPU belong to the machine, not to an item. `ai/maquina.ProviderVigiado` checks before every call the CPU temperature (above `MAX_CPU`, 95 °C, it waits until below `RETOMAR_CPU`, 85 °C, for at most 15 minutes) and the available memory (`MIN_MEMORIA_GIB`, 4 GiB); with the local model also the GPU before the first call and after the load (`ai/gpu.py`, on `OLLAMA_LOG`; also after a call that failed with the model loaded) and whether Ollama still answers with the model loaded. A brake raises `ExecucaoInterrompida`, a subclass of `SystemExit`, so the per-item `except Exception`, the retry of the side analysis and the per-pauta handlers of the scripts let it through; the pipeline logs `Execução interrompida: <reason> (N notícia(s) entregue(s) antes; ...)` and `main` exits with status 1. What was not delivered stays for the next run. How the owner is told about a stop is a proposal in `docs/roteiro-fase4.md`.
- **Time budget.** No new item starts after `MAX_RUNTIME_MIN`; the systemd unit kills the process at 4 hours.
- **The Telegram token must not reach the logs.** The token is part of the request URL and `requests` errors quote the URL, so `delivery/telegram._post` re-raises with `from None` and without the URL.

### The input budget

`summarizer.montar_entrada()` builds the message for the episode and keeps it inside a character limit, so the provider never has to truncate it:

- Headers, the editor's notice (`AVISO DO EDITOR-CHEFE`), the block of sides (`LADOS DA PAUTA`) and the reminder are never cut. The budget sets aside for the block the size it really has. The one exception is the generation input, built before the thin sides and the word budget are known (both come from the cut itself): there the reserve is `lados.reserva_do_bloco()`, the size of the block with every side thin and the budget written with the longest numbers and the notice of little material, capped at `MAX_BLOCO`, which costs up to about 250 characters. Since the final input uses the same reserve, it carries the same cut that was counted. The texts share what is left: each keeps its ceiling (5000 characters for the principal, 3000 for each of up to 2 related articles); if they do not fit, the principal gets about half and the related ones split the rest, and unused share is passed on. A related article that would get less than 400 characters is dropped, and the notice only counts and names what was actually included.
- Within its share, each text is cut by relevance (`recorte.recortar()`), in every call that carries source text: the generation, the revision of the script and the full revision, each with its own space. What enters, in this order of priority: the lide (`recorte.lide()`: the first paragraphs until they add up to 400 characters, skipping lines shorter than 60 characters, lines that look like a photo caption or a site call, such as "Ouça este conteúdo", "Compartilhar matéria" and "... — Foto: ...", and a line that repeats the title); the paragraphs that contain the evidence excerpts of the sides and of the caveats (`lados.trechos_de_evidencia()`, one excerpt of each side and caveat at a time, so no side is starved when space is short; an excerpt is searched in every text of the pauta); and the rest of the text, in order, up to the first paragraph that does not fit. A paragraph is a non-empty line. What enters is shown in the order of the text, with `[...]` where something was skipped, so the chronology is kept. With no excerpts and no skipped lines the cut is the beginning of the text ending at a paragraph end (a text longer than its ceiling used to be cut at exactly 5000 or 3000 characters, mid-sentence; it now ends at the last whole paragraph). `Entrada.recortes` says, per source, which paragraphs entered and why (`lide`, `trecho do lado N`, `trecho da ressalva N`, `ordem do texto`) and which paragraphs with an excerpt were left out; those are also logged as a warning.
- The limit comes from `Summarizer._limite_da_entrada()`. With Ollama it is `OLLAMA_NUM_CTX` minus the output reserve and a margin, converted to characters, minus the system prompt. The reserve is the smaller of `OLLAMA_NUM_PREDICT` and `LLM_RESERVA_SAIDA`, because `num_predict` may be larger than the window itself; a call that limits its own output reserves only that (the side analysis reserves `MAX_SAIDA_LADOS`, 1200 tokens, which leaves it about 15 thousand characters of text before the first measurement and about 18 thousand after it). With an OpenAI-compatible provider the limit is `LLM_MAX_PROMPT_CHARS`; if a message still exceeds it, `OpenAIProvider` cuts it and logs an error.
- Characters per token start at a conservative 3.0 and are then measured from `provider.ultimo_uso` after every call (90% of the lowest value seen).
- The full revision carries the original episode too, so its source text is rebuilt with what is left of the window and can be much shorter than in the generation call. The revision of the script carries only the script, so it leaves more room for the sources. Both redo the cut by relevance for their own space and carry the same block of sides, with the thin sides as counted for the generation. The correction of the summary reuses the excerpts of the generation call, unchanged.
- The side analysis does not share this budget: it reads the whole texts (the principal and up to 2 related articles) in the space of its own call. Only if they do not fit are they cut, each in proportion to its size and at a paragraph end, with a warning in the log and the cut in `Analise.cortes`; the new attempt, which carries the correction request, reads less text in that case. The limit of the generation input is computed after the side analysis, so it already uses the characters per token that call measured.

### The side analysis

The analysis asks the LLM for the question in dispute within the story ("questão": a single question that the actors answer in opposite ways, such as "A empresa descumpriu o contrato?") and for the sides. A side ("lado") is one answer to that question, held by named actors: accusation against defence, decision against criticism, statement against denial. Every actor who gives the same answer is on the same side, even with different arguments, never one side per actor, and a third side only exists when its answer opposes the other two. Complementary information, different details or the mere sequence of events do not make a dispute, and in doubt the story has no question and one side. The question is about the new fact of the pauta, what the texts report as having happened now; earlier episodes that the texts recap are context. If the question of the new fact has only one side with a named actor, the prompt tells the model to look, about the same fact, for another question on which named actors take opposite positions (in the prompt only: there is no extra call). `Summarizer.preparar()` runs the analysis for every pauta, single-outlet ones included, at temperature 0.1, on the whole texts, each with its outlet and title. The answer is a JSON object whose only required key is `lados`; the question comes first so the model states the dispute, then the answer of each named actor with a literal excerpt that proves it, and only then the sides:

```json
{"questao": "one question, or empty", "respostas_por_ator": [{"ator": "Construtora Alfa", "resposta": "Não", "trecho": "literal excerpt", "veiculo": "Jornal do Vale"}], "lados": [{"resposta": "Não", "posicao": "one sentence", "atores": ["Construtora Alfa"], "grupos": [], "trecho": "only in a caveat: literal excerpt", "veiculos": ["Jornal do Vale"]}], "motivo": "one sentence"}
```

Only a position with a named actor counts as a side. `atores` are names or specific designations ("Construtora Alfa", "gestão de Duarte", "governo federal"), in the form the texts use most ("Duarte", not the full name). `grupos` are unnamed collectives ("economistas", "especialistas") and vague designations with no qualifier ("o governo", "a empresa"). A position held only by groups is a caveat ("ressalva"): it does not count as a side, gets no analyst, and enters the episode as an attributed question asked by Helena.

`lados.analise_da_resposta()` is the pure function that turns the answer into the sides and caveats in force. Each side of the answer needs a position and at least one outlet of the pauta (tolerant comparison, `qa.mesmo_veiculo`). A generic actor is moved from `atores` to `grupos` in code (`lados.ator_generico`): one whose words are all in `lados.TERMOS_GENERICOS`, which has the unnamed collectives, the vague designations ("o governo", "a empresa") and, since 23/10/2026, institutions with no qualifier ("a campanha", "o ministério", "o tribunal", "o partido", "a coligação"), so "governo federal", "campanha de Lula" and "governo do Espírito Santo" stay actors; and one whose main word (the first that is not an article, a particle or a quantifier) is a collective of people in the closed list `lados.COLETIVOS_DE_PESSOAS`, even with a qualifier ("comunidade de programação", "usuários do fórum", "economistas do Ipea"), unless that word is capitalized, as a proper name ("Comunidade Europeia"). A side that came with groups only is a `Ressalva` (`grupos`, `posicao`, `veiculos`, `trecho`). If one of its groups is an actor of a side, by the name comparison of the QA (`qa.mesmo_ator`), it leaves, with a note in `ajustes`, and its excerpt, if found in the texts, goes to that side together with its outlets. Otherwise it only stays if its `trecho` is in the title or whole text of one of its outlets, with the same check as the excerpts of the actors (literal or near-literal); otherwise it is discarded, with the reason. A side that came with a named actor and lost them all in the check below is discarded and never becomes a caveat, even if it listed groups. A side with neither actor nor group is an invalid answer, unless it is the only side of the answer: then the pauta gets the neutral side at once, with no new attempt, which is the case of a purely informative story. In a side that has a named actor the groups are dropped, since they agree with it. At most `MAX_RESSALVAS` (2) caveats are kept, the first ones, with a warning in the log. The named sides must be at most 3, each with an actor that no other side has. The question only stays with two named sides or more, each with its own `resposta`, different from the others (compared without case, accents or punctuation); with one named side the question is dropped, and two or more named sides without a question are invalid. With no named side at all the pauta gets the neutral side (`lado_unico()`: every outlet, no actors, position "relato dos fatos, sem lados definidos") and its caveats are discarded, since there is no side for them to qualify; `Analise.descartadas` keeps every discarded caveat as a pair with its reason (no proven excerpt, more than 2 caveats, no named side). Every outlet of the pauta must be in some side or caveat of the answer as it came, before anything is discarded. One outlet may report more than one side. Actors are compared without accents, case, articles or particles (da, de, do, das, dos, e), and a name contained in another is the same actor ("Duarte" and "gestão de Duarte"), so it does not separate two sides. `Analise.ajustes` lists what the code changed in the answer.

With a question, the answer must also carry `respostas_por_ator`: for each named actor, its answer to the question and an excerpt copied literally from the text of an outlet of the pauta (an actor may come in more than one entry; every proven excerpt is kept). `_conferir_atores()` keeps in each side only the actors whose proven answer is the side's: the excerpt must have at least `MIN_TRECHO` characters, bring the actor's answer (see below) and be in the title or whole text of that outlet, even when the call read a cut of it, literally (spaces, quotation marks and case are normalised, and quotes or ellipses around it are ignored; the comparison is `recorte.literal()`) or near-literally (`recorte.localizar_trecho()`): compared word by word, ignoring punctuation, case and the kind of quotes, some contiguous stretch of the text may differ from it by at most one word in ten (replaced, added or missing; rounded down, so an excerpt of fewer than ten words must have the same words), and no difference may involve a negation (não, nem, nunca, jamais). An excerpt accepted near-literally is replaced by the stretch as it is in the outlet, which is what locates its paragraph in the cut by relevance, and `Evidencia.trecho_do_llm` keeps what the model wrote; the same check applies to the excerpts of the caveats. When the answer has two sides or more with a named actor (counted before the check), the excerpt must also bring the actor's answer; with a single side there is no dispute to invent, so the excerpt only has to be in the text, and an adjustment records it (since 24/10: on 23/10, the check took the only actor of the A14, whose excerpt was "a OpenAI admitiu..."). An excerpt brings the actor's answer (`lados.traz_a_resposta`, `Evidencia.prova`; with a dispute, an entry counts only when `Evidencia.vale`) when there is, in this order: a position verb of `ai/verbos.py` in the excerpt; or one in the sentence of the text where the excerpt is (`lados.frase_do_trecho`; the sentence is also split at ";", so in a title "A quer X; B defende Y" the verb of B does not count for the excerpt of A, the case of the N27 of 23/10); or the excerpt is a direct quote (between quotes, a curly quote opened in one paragraph staying open in the next, or a line of speech marked with a dash); or the sentence names the actor and has a decision verb (`verbos.FORMAS_DE_DECISAO`: determinar, decidir, suspender, mandar, participles included; a separate list, not position verbs; the QA uses only its participles, in the passive with the actor as agent), since whoever decides answers in favour of the decision; or an attribution marker in the sentence ("segundo ele", "de acordo com ela", "na avaliação dele"). An excerpt that only describes the actor's conduct ("admitido falhas técnicas") does not. Measured on the 127 recorded analyses of phase 3 and of 17/10 (`data/agrupamento/correcoes_20261023/conferir_item2.py`): it removes the three invented disputes of 17/10 (A46, N69, N55, the last one through the collective rule) and loses the three analyses of the pauta 71+85, whose TSE excerpt has no verb, quote or marker, before the new attempt. Five known limits: the verb of the sentence may belong to another actor (Kassio passed through Lula's "disse" in the A63; the split at ";" only closes the case of two clauses joined that way); the check sees whether the excerpt brings an answer, not which one, and nothing compares the answer with the position of the side: in the A63 of 17/10 and 24/10 Kassio got "Sim" to "was it undue interference?", which is Lula's answer, and Lula a quote starting with "Não" (since the third decision of 24/10 a two-sided dispute requires "Sim" and "Não", see the new attempt below, which catches that shape but not a clean "Não" on the wrong side); who said a quote is not checked; the decision verb counts for any decision of the named actor (a text saying "a Sony decidiu encerrar" would let the Sony of the N69 through); and the check still does not see whether the analysis chose the right question. A decision verb outside the list ("multar", "condenar") does not count. An actor with no excerpt that holds is dropped and listed in `Analise.recusados` (`Recusado`: actor, excerpt and reason, not in the text or without the answer), and so is one with no entry, which is listed in `Analise.faltam`; both get the new attempt (see below); an actor placed in a side whose answer differs from its own moves to the side with its answer, if there is one, or is dropped; two answers are the same when one starts with the other ("Sim" and "Sim, é desinformação"). A side left with no actor is discarded, as said above. A question that is not a yes-or-no one (starting with qual, quais, como, quem, o que, por que, onde or quando, `lados._QUESTAO_ABERTA`) leads to the neutral side, with no caveats and no new attempt, whatever the number of sides (second decision of 24/10/2026): the question in dispute is answered in opposite ways, different plans or priorities are not a dispute, and a single side with one of the actors, when the check removed the other, unbalances a story that compares two of them (the N27 of 24/10 kept only Flávio, and the analyst gave his plan two turns against one for Lula's). From the first decision of 24/10 until then, an open question invalidated only an answer with two named sides or more. Measured on the 185 recorded analyses (`data/agrupamento/correcoes_20261024b/medir_questao_aberta.py`): only the two of the N27 had an open question, and both stay right by the owner's answer key. A question with no `respostas_por_ator` is an invalid answer. Before adoption, (a) the split at ";" and (b) the open question with a dispute were each measured on the 147 recorded analyses, and each changed only the N27. Without a question nothing is checked and the actors stay as they came. `Analise.respostas` keeps every entry with the result of the check, and `Lado.trechos` the excerpts of the actors that stayed.

A side whose actors appear in at most one sentence of the texts that the generation receives is a thin side ("lado fino", `Lado.fino`; only in pautas with two sides or more, `lados_finos()`). The count is done by the code, `lados.mencoes()`, over the title and the sentences of each text as cut by relevance for the generation (`lados.com_mencoes()`, called by `Summarizer.preparar()` once the cut exists; the revisions keep that count), with the name rule of `qa.ator_citado` ("o prefeito" does not count for "Duarte"), and is kept in `Lado.mencoes`; the excerpts listed by the model do not enter it. Since the fourth decision of 24/10/2026 a mention that only appears inside quotation marks does not count (`lados.fora_das_aspas`, applied to each sentence by `_frases_fora_das_aspas`): another actor speaking of him ("“Seria prudente que o comandante...”, declarou" the minister, in the A79) and a name quoted as a title (the channel “Exército de Lula”, in the N13). Straight double quotes, curly double quotes (“ ”, « », „) and curly single quotes count; the straight single quote does not, since it is also an apostrophe, and a closing curly single quote with none open is an apostrophe ("Sant’Ana"); a curly double quote left open continues in the next paragraph only when that paragraph opens with quotes. The actor's own speech counts when the text names him outside the quotes ("“...”, afirmou Lula"); when his name is only inside his own quote (Lula's "Exército do Lula" in the N13), it does not, as with any sentence that names him only by his office. Measured on the 69 recorded analyses with a dispute (`data/agrupamento/correcoes_20261024d/medir_aspas.py`): 46 divisions of the budget and 5 thin sides change, and every sentence that stops counting has the name only inside quotes; in the A79 the commander goes from 2 sentences to 1 (thin, target 90), and in the N13 Lula from 5 to 3 (the technical area on the channel, and his own quote that names him only through the channel; target 360 to 270). Since 24/10/2026 the surname alone also counts for an actor whose name is a person's (`lados.sobrenome`: two words or more, all capitalized except particles, the last one not after a particle; "Valença" for "Teodoro Duarte Valença", nothing for "campanha de Lula" or "Corpo de Bombeiros do Amazonas"), and since the fourth decision only when the name is a person's (`lados.nome_de_pessoa`: no organization word in it, a closed list such as Agência, Banco, Justiça, Sindicato, Coligação, and, in the texts outside quotes, more often without an article right before it than with one, "o Sindipetro Unificado"; "o ministro Waldez Góes" does not count, since the article goes with the office; measured on the recorded analyses, `medir_sobrenome_de_organizacao.py` and `medir_pessoa.py`, it separates the 6 organizations, among them the "Unificado" of the N92 and the "Brasil" of the Agência Brasil, which counted sentences about the country in the A104, from the 22 persons, and only counts of single-side analyses change), unless another person cited in the texts or an actor of another side has the same surname (`lados.outro_com_o_sobrenome`: the surname right after a capitalized word, with only spaces or particles between them, that is not a word of the actor's name, a sentence opener or a title such as "Ministro"; a comma separates two people). This is only for the count, not for the QA rule. Measured on the 61 recorded analyses with a dispute (`data/agrupamento/correcoes_20261024b/medir_sobrenomes.py`): 28 divisions of the budget and 3 thin sides change, and the surnames that start to count (Amorim, Cueva, Góes, Janones, Marques) are all of the right person; in the A79 the minister goes from 2 sentences to 4 and the split from 350 and 350 to 430 and 230. The sources carry little material for a thin side, so the block tells its analyst not to expand beyond what the sources carry, and the budget gives him a target in proportion to the mentions, at most 90 words per sentence of his side: 90 with one sentence, below the minimum of 120 of the other analysts (third decision of 24/10/2026). The QA minimum is at most `QA_MIN_LADO_FINO`; the cap of `QA_MAX_LADO_FINO` (200) is a diagnostic of `scripts/testar_episodio.py`.

There is at most one new attempt per analysis (`lados.analisar_lados()`). An invalid answer or a failed call gets it with the same input plus `pedido_de_correcao()`, which carries the validation error, the refused answer and a reminder to group the actors by their answer to the question; `Analise.primeira` keeps the refused attempt, and if the second attempt is not valid either, the pauta goes on with the neutral side and no caveats, with a warning in the log, and the episode has one analyst. A valid answer in which an actor is in a side with no entry in `respostas_por_ator`, or with entries none of which holds (`Analise.recusados`), gets it with `pedido_das_respostas()`, a single request that names the actors without an entry and gives, for each refused one, the excerpt and the reason, and asks for each the sentence, copied literally, in which the text brings the actor's answer: if the new answer is valid it is the one in force (an actor still without an entry or an excerpt that holds leaves, and `Analise.primeira` keeps the first answer); if it is not, the first answer stays, without the actor, and `Analise.segunda` keeps the refused one. It is the same single new attempt: after the correction of an invalid answer, a refused excerpt asks for nothing more. An open question gets no new attempt: it is the neutral side at once.

In a two-sided dispute the answers of the sides are "Sim" and "Não", one each (`lados.sim_e_nao`, case, accents and a final period ignored; third decision of 24/10/2026); with three sides it is enough that they differ. An answer that is otherwise valid and fails only this keeps its sides, with the reason in `Analise.sem_sim_e_nao` (not a problem), and gets the new attempt too, with `pedido_das_respostas()`: alone, ending with `LEMBRETE_DO_SIM_E_NAO`, or in the same request for missing entries or refused excerpts, adding `REGRA_DO_SIM_E_NAO`. It asks each side and each actor to answer "Sim" if its excerpt affirms what the question asks and "Não" if it denies it, and a question that cannot be answered so to be rewritten as a yes-or-no one about the same fact. The new answer is in force only if it is valid and brings "Sim" and "Não" in two sides; otherwise, for any reason (invalid, failed call, still descriptive, a single side), the first stays, and `Analise.segunda` keeps the refused one: this rule never brings an analysis down, unlike an invalid answer, which ends in the neutral side. When the first already had "Sim" and "Não" and only lacked an entry, the new answer is in force when valid, as before, even without them. Measured on the recorded analyses (`data/agrupamento/correcoes_20261024c/medir_sim_e_nao.py`): 10 of the 65 with a dispute, the same 10 of the measure of the second decision; 2 are the A63 with Kassio's answer swapped, and 8 have the right sides with descriptive answers, which the new attempt should fix. A clean "Não" on the wrong side (Lula's quote starts with "Não vamos aceitar") passes the rule.

The result reaches the generation as the block `LADOS DA PAUTA` (`lados.bloco_dos_lados()`): the question, the sides with their answers, the caveats right after them, the exact cast (Helena plus one analyst per side; Helena presents the question once, at the opening, and each analyst sustains the position of one side; with a single side the analyst explains and does not advocate), how Helena brings each caveat, which sides are thin, the value of `houve_divergencia`, and the word budget: the target of Helena, of each analyst and of the total, each as a single number, the plan of the turns ("Plano das falas: Helena, 6 falas de uns 60 palavras; analista, 5 falas de uns 85. Ordem dos 11 turnos: Helena, analista, ..."), and, when the material is little, the notice that the target is already smaller and is met with what the sources carry, with no new argument (see "The word budget"). The block never exceeds `MAX_BLOCO` characters (1600): the position sentences shrink first, and what still does not fit leaves from the end of the last line, never the cast and the plan. With the plan, 3 of the 155 valid recorded analyses shrink their positions and none is cut. The model no longer decides whether there is a divergence. `PROMPT_LADOS` also says that different strategies, plans or decisions of different actors, each about its own business, do not make a dispute (the case of the N69, with an invented example). The pieces that change together are `PROMPT_LADOS`, `CHAVES_LADOS`, `entrada_dos_lados()`, `analise_da_resposta()`, `_conferir_atores()`, `_separar()`, `TERMOS_GENERICOS`, `pedido_de_correcao()`, `pedido_das_respostas()`, `trechos_de_evidencia()`, `bloco_dos_lados()` with `reserva_do_bloco()`, the prose about the question, the sides and the caveats in `PROMPT_SISTEMA` and `PROMPT_REVISOR`, and `qa.problemas_dos_analistas()` and `qa.problemas_das_ressalvas()`. The list of position verbs lives in `ai/verbos.py` only: the prompts show the infinitives and the QA accepts the inflected forms. The pieces of the excerpt check are `traz_a_resposta()`, `frase_do_trecho()`, `_citacao_direta()`, `COLETIVOS_DE_PESSOAS` and `verbos.FORMAS_DE_DECISAO`.

### The corrections

Every problem found by `qa.problemas_com_campo()` is a `Problema` with the field of the episode it belongs to, and `summarizer.tipo_de_correcao()` picks the single correction the episode gets from those fields:

- **Title** (`"titulo"`): every problem is in the title. A short call with `PROMPT_TITULO` rewrites only the title from the summary. It receives the summary, the actors of the sides and the titles already refused, each with its reasons, no source text, and answers `{"titulo_reescrito": "..."}`. It is the only correction that may be repeated: if the new title still fails, a second call carries both refused titles (`TENTATIVAS_DO_TITULO`), because the model tends to swap one proportion for another ("maioria" for "70 dos 120").
- **Summary** (`"resumo"`): every problem is in `resumo_didatico`. A short call with `PROMPT_RESUMO` rewrites only the summary. It receives the same excerpts that went to generation (`Entrada.artigos`), whether there is a divergence, the problems and the original summary, and answers `{"resumo_didatico": "..."}`.
- **Script** (`"roteiro"`): every problem is in `roteiro_podcast` (words per character or in total, the match between analysts and sides, caveats, attributions and numbers inside a turn) or in the role of a character. A call with `PROMPT_ROTEIRO` receives the sources, the block of sides, the characters, the problems and the original script, and answers `{"personagens": [...], "roteiro_podcast": [...]}`. From the characters it returns, the code only takes the role of each name that already existed (`_com_os_papeis`): names and order never change.
- **Full revision** (`"completa"`): problems in more than one field, or in a field with no correction of its own (number of analysts, `houve_divergencia`, `fontes_citadas`, key points, malformed JSON). `PROMPT_REVISOR` receives the sources, the problems and the whole episode, and answers the whole episode.

The answer of a targeted correction is merged into the first version, and the QA runs again on the result. `Summarizer.ultimo_diagnostico` keeps the first version, the kind of correction (`correcao`), the input it used (`revisao`), the refused titles (`titulos_reprovados`) and the last whole episode (`episodio`). The rules about Helena, the analysts and the caveats are written once for the two revisions, in `_REGRAS_DO_ROTEIRO` (`ai/prompt.py`).

### The LLM output contract

The episode is a JSON object with 8 keys (`titulo_reescrito`, `resumo_didatico`, `pontos_chave`, `por_que_importa`, `personagens`, `roteiro_podcast`, `houve_divergencia`, `fontes_citadas`). That shape is repeated in several places that must change together:

- `SCHEMA` / `REQUIRED_KEYS` in `ai/llm.py`. The schema is not sent to the provider (Ollama gets `format="json"`, OpenAI gets `json_object`); only the presence of the required keys is enforced, in `parse_json`.
- The prose in `ai/prompt.py` (`PROMPT_SISTEMA` and `PROMPT_REVISOR`) and the reminder (`LEMBRETE`) appended by `summarizer.montar_entrada`. `PROMPT_TITULO`, `PROMPT_RESUMO` and `PROMPT_ROTEIRO` each ask for one or two of those keys alone, and the revision of the script closes its input with `LEMBRETE_DO_ROTEIRO`.
- The consumers: `ai/qa.py`, `audio/tts.py` and `_render_item` in `delivery/telegram.py`.

There is a second, much smaller contract: the grouping verdict (stage 3 of the news grouping, see "Unfinished or dormant code"). The model receives one provisional pauta, with its articles numbered from 1, and answers with a JSON object whose required keys are `tipos`, `grupos` and `isolados`:

```json
{"tipos": {"1": "fato_unico", "2": "fato_unico", "3": "varios_fatos"}, "grupos": [{"principal": 1, "membros": [{"id": 2, "relacao": "mesmo_acontecimento"}]}], "isolados": [3], "motivo": "one sentence"}
```

`tipos` classifies every article first: `varios_fatos` is a text that covers several unrelated events (agenda, weekly roundup, bulletin, live coverage) and can never be part of a group. `membros` lists the other articles of the group (never the principal), `relacao` is `mesmo_acontecimento` or `desdobramento`, and every number must appear exactly once between `grupos` and `isolados`. A missing or invalid type, id or relation discards the whole verdict and leaves every article on its own. From a valid verdict the code takes who stays together, the types and how the articles relate: an article typed `varios_fatos` is removed from its group even if the model grouped it, and the model's choice of `principal` is ignored. Its pieces must also change together:

- The prose in `PROMPT_AGRUPADOR` (`ai/prompt.py`).
- `CHAVES_AGRUPADOR`, `TIPOS`, `RELACOES`, `entrada_agrupador()` (the text the model receives), `problemas_do_veredito()` and `compor_pautas()` in `processing/agrupamento.py`.

`parse_json(text, chaves)` and `chat_json(system, user, chaves=, temperatura=, max_saida=)` take the required keys and the sampling options per call. With no extra arguments a call is the episode call: `REQUIRED_KEYS` and the values from `.env`. `num_ctx` is never set per call, because changing it makes Ollama reload the model.

The examples in the prompts (questions, actors, outlets, roles, proportions) are invented and come from neither sample in `data/agrupamento/`: when the side analysis had "O canal deve ser suspenso?" as its example question, the model gave that same question to two pautas of the same story, the right one by coincidence and the wrong one. Keep any new example away from the content of the samples (grep each name in all of them), and use no outlet that exists: in a prompt about attribution, a real outlet is a name the model may put in an episode where it is not a source. On 23/10/2026 "Jornal do Vale" and "Diário do Litoral", which exist, were replaced in `PROMPT_SISTEMA` by invented ones (`tests/test_summarizer.py` checks that they stay out); the tests and this file still use them, since the model never reads those.

The presenter name `Helena` is fixed by the prompt and mapped to a fixed voice in `tts.VOZ_FIXA`. The analysts' names come from `ai/elenco.py`, by slot (the slot i is the analyst of side i; with one side, the first): in each slot the first name that is neither the name nor the first name of an actor of the analysis (`elenco.mesmo_nome`). The names barely appear in the phase 4 samples, so they rarely coincide with a person cited who is not an actor. Each slot has its voice, of the gender of its names (`tts.VOZES_DIVERSIDADE`, same position: Antonio, Thalita, Gustavo), and `tts.atribuir_vozes` gives each listed name the voice of its slot; any other name gets, in declaration order, a voice left over. Until 24/10 every analyst got a voice by declaration order, so a single female analyst spoke with the first, male, voice.

### The word budget

The number of words of the script follows the material the generation receives (`ai/orcamento.py`, item 3 of the plan of 19/10/2026, adopted on 23/10/2026). `Summarizer.preparar()` computes it once, from the words of the cut texts (`orcamento.palavras`: the cut of each text, without the title) and the mentions of each side, keeps it in `Entrada.orcamento` (and `ultimo_diagnostico["orcamento"]`) and passes it to the block of the generation and of both revisions and to the QA:

- The total target is `FATOR` (1.75, to be calibrated in the regression) times those words, with a floor of `PISO_TOTAL` (300) and a ceiling at the target of before for the cast size (`ALVO_DE_ANTES`: 390, 360 and 285 per character with one, two and three analysts, the centres of 360-420, 320-400 and 260-310). Texts above about 450 words (one analyst) or 620 (two) get the budget of before.
- Helena gets the share of before, between 35% and 45% (`parte_da_helena`: 45% with one analyst, 35% with two or three). With one side the analyst gets the rest; with two or more the analysts split it in proportion to the mentions of their side (`Lado.mencoes`), each with at least `MIN_ANALISTA` (120) words. No character gets more than `MAX_ALVO` (430), below the 480 the prompts used to ask. With two sides or more, the target of each analyst is also at most `MAX_POR_FRASE_DO_LADO` (90) words per sentence of his side (zero counts as one; a side with no count has no cap), and this cap beats the minimum: with one sentence the target is 90 (third decision of 24/10/2026; across the runs since 23/10, the marks of the analysts with a dispute were 6,7 per thousand words up to 50 words per sentence of material, 6,8 from 50 to 90 and 19,8 above 90). What the cap removes leaves the total; Helena keeps her share of the total before it, up to 45% of the total that remains, and `Orcamento.reduzido` still looks only at the material of the pauta. Measured without the model (`data/agrupamento/correcoes_20261024c/medir_teto.py` and `conferir_teto_no_codigo.py`): 22 of the 65 recorded analyses with a dispute and 3 of the 20 items change, all by the right count (A79 430 and 230 → 360 and 180, N13 120 → 90, N92 120 → 90); one old analysis of the pauta 79+105 counts "Corpo de Bombeiros Militar" as the commander, a count error that makes its cap looser, not tighter. With the cap, Helena's turns get longer when the analysts have fewer (A79: 5 of 75 instead of 6 of 65). Targets are rounded to tens, half up.
- The plan of the turns (`Orcamento.plano`, a `Plano`; second decision of 24/10/2026) closes the arithmetic of every target. Each analyst gets the turns his target asks with at most `MAX_FALA_DO_ANALISTA` (90) words each, and at least `MIN_FALAS_DO_ANALISTA` (2). Helena opens and closes and speaks between the rounds: in each round, the analysts who still have a turn speak in the order of the sides. She has one turn more than the analyst who speaks most, and her target is divided among them. The size of each turn is rounded to 5. With one analyst of 430 and Helena with 350: Helena 6 turns of about 60, the analyst 5 of about 85, 11 turns; with two analysts of 360 and 120 (the N13): Helena 5 of 50, 4 of 90 and 2 of 60, in the order H 1 2 H 1 2 H 1 H 1 H. `Orcamento.turnos` is the length of the order. Until then the block asked a single number of turns (the total divided by 75) of 70 to 80 words for everyone: the model followed it in 7 of 8 items of the short run of 24/10, Helena, who speaks every other turn, got 49% of the words against the 35% to 45% of her target, and the analysts could not reach theirs. The plan of the 20 items of the regression, checked without the model (`data/agrupamento/correcoes_20261024b/planos.py`), always closes.
- The block gives each target as a single number (since 24/10; on 23/10 they were ranges of ±10%, and the model aimed at the floor of every range: the scripts came out with 66% of the target). The QA minimum is 60% of the target (`minimo_do_qa`; 75% until the fourth decision of 24/10), never above the minimum of before, so it is always below the target, and the difference is a margin; the maximums are those of before. The QA message of a character or total outside its limits says what is accepted and the target of the block, and both revisions aim at the target of the block, not at the middle of the accepted range, expanding with what the texts carry, with no new argument.

The prompts no longer hard-code word, turn or thin-side numbers: `PROMPT_SISTEMA`, `_REGRAS_DO_ROTEIRO`, `LEMBRETE` and `LEMBRETE_DO_ROTEIRO` point to the block, and `PROMPT_SISTEMA` tells the model to count the words of each character and expand the turns to the target with what the texts carry, with no new argument (the instruction to expand, which the scripts of 17/10 followed with turns of 96 words, had left the prompt on 23/10). With the sections of 23 and 24/10, `PROMPT_SISTEMA` grew from 7,843 to 9,604 characters, and the plan adds about 200 characters to the block (about 450 with one side, up to about 900 with two). On a single source the generation comes after the side analysis, which measures the characters per token (3.26 to 3.41 in the runs of 23 and 24/10), and from 3.2 up the ceiling of 5,000 characters of the principal binds before the window, so no text loses room; only with the initial 3.0, if the analysis failed, a text of 5,000 characters would lose its last paragraph. With several outlets the window binds, and the generation loses up to about 1,960 characters of text against the prompt of before 23/10 (1,761 from the prompt and about 200 from the plan in the block). Changing `QA_*` in `.env` only changes the caps of the minimums and the maximums. The 8 to 9 sentences of the summary are still in `PROMPT_SISTEMA` and `PROMPT_RESUMO`. The pieces that change together are `ai/orcamento.py`, `lados._alvo_do_elenco()` with `reserva_do_bloco()`, `qa.alvo_de_cada_personagem()`, `qa.limites_de_cada_personagem()`, `qa.limites_do_total()` and the prose about the block in the prompts.

### Logging and the log-summary script

`logging_setup.py` configures the `techdigest` logger once: console at `LOG_LEVEL`, plus `data/logs/techdigest.log` always at DEBUG (rotating, 2 MB x 7). Modules log through `logging.getLogger("techdigest.<module>")`.

`scripts/resumo_lotes.py` parses that file with regexes over the line format and over exact message texts (`=== TechDigest iniciando ===`, `Execução concluída: N notícia`, `Item pulado pelo QA`, `Item descartado`, `Falha ao entregar`, `Execução interrompida:` (a machine brake, shown in the table with its reason), `Execução não começou:` (the model lock was busy, listed after the table), and the Ollama metrics line with `tok/s`, `RAM disp.=`, `CPU=`, `GPU=`). Rewording those messages or changing the format string breaks the script silently. The metrics line is logged once per LLM call, so its averages now include the short side-analysis call of every item.

## Unfinished or dormant code

- **Related articles.** `Summarizer.process(principal, relacionados)`, the prompts, the input budget and the QA source rule support several sources for one story, but `pipeline.py` never passes `relacionados`, so every delivered episode is single-source. The side analysis does run in the pipeline, since it is part of `process`: a single-source item with two sides gets two analysts and `houve_divergencia` true. Multi-source generation is only exercised by `scripts/testar_episodio.py`.
- **News grouping, phases 1 to 3 of 4.** `processing/agrupamento.py` groups articles that tell the same story (the same event, or a direct follow-up of it within the collection window) into "pautas": stages 1 and 2 score every pair by title and text similarity and form provisional pautas of up to `AGRUP_MAX_ARTIGOS` articles (`AGRUP_LIMIAR`, 0.18, calibrated on a first labelled sample and kept after a second one, collected on 2026-10-12: of the 8 pairs scoring between 0.15 and 0.18 there, five were different facts (one generic article about AI against three unrelated AI stories, and one phone offer against two other offers) and none was a new pair of the same fact, so lowering the threshold would only add false groups); in stage 3 the LLM reads the first `AGRUP_CHARS_ETAPA3` characters of each article, confirms each provisional pauta, and `compor_pautas()` builds the final ones. In a final pauta the `principal` is the article with the longest extracted text and every other confirmed article is a `relacionado`, same outlet or not; the relation (`mesmo_acontecimento` or `desdobramento`) only guides the episode. Only `principal` and `relacionados` go to generation. `duplicatas` (republications, detected by text similarity in stages 1 and 2) are not generated but are delivered with the pauta, so `Pauta.links` includes them; `excedentes` (confirmed articles beyond the limit) are neither generated nor delivered, and today they would come back as candidates in a later run; by a decision of phase 4 they will be marked as seen with the pauta and listed in its text, like the duplicates. All of this, plus `extractor.extrair_em_lote()` and the `AGRUP_*` / `EXTRACAO_*` settings, is used only by `scripts/testar_agrupamento.py`: the pipeline does not group yet, and the call to the LLM for stage 3 lives in that script. - **State of phase 3 (frozen on 2026-10-14, branch `agrupamento-fase3`, not merged).** Ready, but used only by the diagnostic scripts: the grouping in three stages; the multi-source generation; the side analysis on the whole texts, with literal or near-literal excerpts, caveats with their own excerpt and one new attempt; the cut by relevance in every call that carries source text; the QA rules listed above; the GPU checks of `ai/gpu.py`.
