# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TechDigest is a batch pipeline that collects news from RSS feeds (technology + Brazilian politics), has an LLM write a summary and a multi-voice podcast script for each item, synthesizes the audio with Edge-TTS, and delivers each item to Telegram. It is meant to run unattended from a systemd timer. The user unit of the Ollama server and a target for test sessions are in `deploy/systemd/`; the unit of the pipeline and the timer are not in this repo yet, and the timer stays off until the owner says otherwise. Since the merge of phases 1 to 4 into `master` (fast-forward, 05/11/2026; later ones on 06/11 and 07/11) this folder is the production code: `master` runs with `AGRUPAMENTO_ATIVO=false`, and the owner starts the real runs by hand (see "Production state" in the repo notes).

Everything in the codebase is written in Brazilian Portuguese: identifiers, comments, docstrings, log messages, LLM prompts and commit messages. Keep new code consistent with that.

## Commands

```bash
.venv/bin/pip install -e .                       # install (already installed editable in .venv, Python 3.14; requires >=3.11)
.venv/bin/techdigest                             # run the pipeline (same as: .venv/bin/python -m techdigest)
.venv/bin/python scripts/resumo_lotes.py         # per-run summary table parsed from today's log
.venv/bin/python scripts/resumo_lotes.py 07/10   # same, for a given day (DD/MM); --log <file> reads another log
.venv/bin/techdigest --simular <folder> --banco-origem <digest.db>   # a real run delivering to files, on a copy of the db
.venv/bin/python scripts/testar_agrupamento.py   # grouping diagnostic: no Telegram, digest.db opened read-only, LLM only with --etapa3
.venv/bin/python scripts/testar_episodio.py --amostra <file>   # generates a few episodes from a saved sample: LLM only, nothing delivered
.venv/bin/python scripts/checar_fidelidade.py    # checks those episodes against the source texts of their pautas: no LLM, no network
.venv/bin/python scripts/refazer_qa.py <folders> # reruns the current QA on recorded episodes: no LLM, no network
.venv/bin/pip install -e '.[dev]'                # dev extra (pytest)
.venv/bin/pytest                                 # tests
systemctl --user start techdigest-teste.target   # test session: brings up the Ollama of the user unit (stop it at the end)
```

- Manuals of the diagnostic scripts (`testar_agrupamento.py`, `testar_episodio.py`, `checar_fidelidade.py`, `refazer_qa.py`), what the tests cover, the simulation and the Ollama user unit: `docs/referencia/scripts.md`. Read the part you need before running or changing any of them, `simulacao.py`, `deploy/systemd/`, `ai/maquina.py` or `ai/gpu.py`.
- `.venv/bin/pytest` runs offline: `tests/conftest.py` turns off the `.env` and points the database, logs, audio, deliveries, Ollama log and model lock to a temporary folder, and no test calls an LLM or reaches Telegram. There is no linter and no formatter configured. `requirements.txt` is empty and gitignored; dependencies live in `pyproject.toml`.
- **Running the pipeline has real side effects**: it calls the LLM, sends messages and audio to the configured Telegram chat, and marks URLs as seen in `data/digest.db`. The simulation below is real too, except for the delivery and the database: it calls the LLM and Edge-TTS and takes the model lock. Do not run either just to check a change; exercise the individual function instead (e.g. `collect_rss()`, `extract_full_text(url)`, `qa.problemas(result, veiculos, lados, ressalvas, textos)`).
- **Simulation** (`techdigest --simular <folder> --banco-origem <digest.db>`, `simulacao.py`): collection, extraction, LLM and TTS are real; the delivery goes to files and the database is a copy, and no path of it calls the Telegram API. Put the folders under `data/simulacoes/`. Details in `docs/referencia/scripts.md`.
- Always enter through `techdigest.main` (the console script or `python -m techdigest`). `python -m techdigest.pipeline` skips `setup_logging()`, so nothing reaches the log file.
- System requirements outside pip: `ffmpeg`/`ffprobe` on PATH (audio concat and duration), network access for Edge-TTS, and an Ollama server at `OLLAMA_HOST` when `LLM_PROVIDER=ollama`.
- The Ollama server runs as the user unit `deploy/systemd/ollama.service`, brought up for test rounds with `systemctl --user start techdigest-teste.target` and stopped at the end, never with `ollama serve` by hand: the GPU checks of the scripts refuse the log of another start of the server. Installation, log, `LLAMA_ARG_CACHE_RAM=0` and the GPU checks: `docs/referencia/scripts.md`.

## Configuration

- All settings are fields of `Settings` in `src/techdigest/config.py` (pydantic-settings), read from `.env` at the repo root. The env var name is the field name in upper case (`max_news` → `MAX_NEWS`).
- Reading `.env` is denied in `.claude/settings.json`. Use `config.py` as the reference for which keys exist and their defaults, and ask the user for actual values. The feed list in particular comes from `RSS_FEEDS` (comma-separated) in `.env`; the defaults in code are not what runs in practice.
- Every module creates its own `settings = Settings()` at import time, and `ai/qa.py` copies the `QA_*` limits into module constants at import. Settings therefore cannot be overridden in one place at runtime; an override has to be in the environment before the modules are imported.
- `LLM_PROVIDER=ollama` selects `OllamaProvider`; any other value selects `OpenAIProvider`, which covers every OpenAI-compatible endpoint (Groq, OpenRouter) through `OPENAI_BASE_URL`.

## Editorial rules

The rules below are the ones in force today. They are referred to by name, not by number: the comments in the code mention "regra 1", "regras 2, 3 e 6" and similar, but the numbered list is not in the repository and those numbers could not be matched to specific rules. Do not infer a number's meaning from the code; ask the owner.

Two criteria decide how these rules change. A verb that presents the statement as true never enters the list of position verbs ("constatar", "revelar", "reconhecer", "admitir"): in a pauta with a dispute it takes a side. A new verb that passes that criterion goes into the single list of `ai/verbos.py`, and relaxing the analysts rule with it is a relaxation; separate lists only for a verb that serves one rule and not the other (the decision verbs are the case: they prove an actor's answer in the side analysis and, in the QA, count only in the passive with the actor as agent, but attribute no position). And a rule that relaxes the QA goes in directly, while a new rule that rejects goes first through a diagnostic (`scripts/checar_fidelidade.py`, with `scripts/refazer_qa.py` to see its effect on the recorded episodes) and only then into `ai/qa.py`; extending the closed list of an existing rule that rejects counts as a new rule.

**Verified by code.** An item that violates one of these gets one correction (see "The corrections" below) and, if it still violates, is skipped (`ai/qa.py`):
- Summary with 7 to 10 sentences (`resumo_didatico`). The prompts ask for 8 to 9, plus one closing sentence about the debate when `houve_divergencia` is true, to leave a margin. The count is the old `master`'s (before the merge of 05/11/2026), every ".", "!" and "?", except one glued to a letter or a digit (`qa._FIM_DE_FRASE`, decision of 25/10/2026): the dots of "Hardware.com.br" and of "1.200" do not end a sentence; abbreviations and ellipses still count as before. It is not `qa.frases()`, the split used by the mentions, the analysts and the caveats, which already never split inside a word and joins abbreviations. Measured on the 158 recorded episodes (`data/agrupamento/correcoes_20261025/medir_falsos_positivos.py`): 17 summaries count fewer sentences, none goes below 7, and one episode becomes approved (the 26+69 of the preview of 25/10, from 12 sentences to 8).
- Words per character and in total follow the word budget of the pauta (`ai/orcamento.py`, see "The word budget" below). The maximums do not change: 650 per character (`QA_MAX_POR_PERSONAGEM`, the value in force since it was set in `.env`; the default of `config.py` since phase 4) and 1300 in total (`QA_MAX_TOTAL`). The minimum of each character is 60% of the target the block asks of it, and the minimum of the total 60% of the total target, never above the minimums of before: `QA_MIN_POR_PERSONAGEM` (240), `QA_MIN_LADO_FINO` (120) for the analyst of a thin side, `QA_MIN_HELENA_COM_DEBATE` (180) for Helena with two analysts or more, and `QA_MIN_TOTAL` (600). So the minimum is always below the target the block asks for, and the difference is a margin, as with the sentences of the summary. Without a budget (`orc=None`), the minimums of before apply. Below the minimum, the message also says what is missing in each turn by the plan of the block (`qa.o_que_falta`, third decision of 24/10/2026): with the number of turns of the plan, how many words to add to each ("4 falas de uns 49 palavras; o plano pede 4 falas de uns 90: acrescente uns 40 palavras a cada fala, com o que os textos trazem"); with another number, how many words are missing for the target; an analyst with no side has no plan, only the missing words. How far each character is from its target, and the cap of 200 of the thin-side analyst (`QA_MAX_LADO_FINO`), are diagnostics of `scripts/testar_episodio.py`, not QA rules: a cap in the QA is for the owner to decide after the regression. The fraction was 75% until the fourth decision of 24/10/2026, which lowered it to 60% (`orcamento.FRACAO_DO_MINIMO`), a relaxation: since 23/10 the analysts stay between 66% and 73% of their target, and neither the plan of the turns nor the message per turn made them write more; the analyst with full material (target 430) already passed with 240, 56% of the target, and the fraction gives the others the same slack. The plan still asks for the whole target. Measured before: at 60% the regression of 23/10 would have had 12 of 20 approved (4 at 75%), and the third short run of 24/10 6 of 8 (3 at 75%; `data/agrupamento/correcoes_20261024/fracao_do_minimo.py`).
- Every speaking character is declared in the cast, and every declared character speaks.
- Source text with at least 1200 characters, so headlines alone never become an episode (`pipeline.py`).
- Article published no more than 7 days ago (`MAX_IDADE_DIAS`).
- When an episode has two or more outlets as sources, every one of them appears in `fontes_citadas` (accent- and case-insensitive, one name may be contained in the other, compared by whole words). Single-source episodes are not affected, and the pipeline only produces single-source episodes today.
- Title without percentages or proportions (`proporcoes_no_titulo`): no percentages, no "x vezes" (nor "dobro", "triplo", "quádruplo") and no proportions ("metade", "um terço", "três em cada quatro", "6 de 11", "a cada 9 horas", "maioria", "minoria", "maior parte", "grande parte"). An absolute quantity passes, in digits or written out, with or without "quase", "mais de" and similar ("12 mortos", "doze mortos", "mais de 100 mortos"), and so do years, ordinals and names that carry a digit ("Eleições 2026", "1º turno", "BR-101").
- Analysts per side (`problemas_dos_analistas`), for every episode. The side analysis (see "The side analysis" below) says how many sides the pauta has, from 1 to 3. The episode must have exactly one analyst per side (Helena does not count), and `houve_divergencia` must be true if and only if there are two sides or more. With two sides or more there must be a one-to-one match between analysts and sides in which each analyst has one sentence that cites an outlet of that side, uses a position verb and names an actor that only that side has. Since 24/10/2026 (third decision) a sentence that cites an outlet of the side and has a decision verb in the passive with that actor as agent also presents it (`verbos.agentes_da_decisao`: a participle of `FORMAS_DE_DECISAO`, the same list the side analysis uses, followed within 3 words by "por", "pelo", "pela", "pelos" or "pelas"; the agent runs to the next verb, conjunction or semicolon, so with two agents only the first counts), as in "segundo a Agência Brasil, a suspensão do canal foi determinada por decisão do presidente do TSE, Kassio Nunes Marques" (the A63 of 24/10, whose text only carries Kassio that way). Measured on the 44 recorded episodes with two sides or more (`data/agrupamento/correcoes_20261024c/medir_passiva.py`): only that sentence starts to count. An actor counts as named when the sentence has more than half of the words of its name that no actor of another side uses, so "Duarte Valença" stands for "Teodoro Duarte Valença", while a name of one or two words must appear in full. The position verbs are a closed list of inflected forms in `ai/verbos.py` (27 verbs, among them "informar", "concluir", "dizer" and "declarar", the verbs of a technical body or a spokesperson, and "classificar" and "ressaltar", added on 23/10/2026; third person present, preterite and imperfect, singular and plural, the gerund and the infinitive), compared as whole words and accent-sensitive, so "negócio" is not "nega" and "crítica" is not "critica". The compound preterite counts as a pair, an auxiliary (tem, têm, tinha, tinham, teria, teriam, havia, haviam) followed by the participle ("havia classificado", "tinha dito"): the participle alone does not count, since "dito" and "pedido" are also nouns. "Considerar", "justificar", "pedir" and "chamar" stayed out (owner's decision of 23/10/2026).
- Caveats (`problemas_das_ressalvas`). Each caveat of the pauta must appear in a turn of Helena that contains a question mark and has one sentence that cites an outlet of the caveat, names one of its groups and uses a position verb ("Segundo o Jornal do Vale, economistas alertam que... Como você vê isso?"). The group counts by its main word (the first one that is not an article, a particle or a quantifier), in any number or gender, so "pesquisadora" stands for "pesquisadores"; a form of a position verb is not a group term ("critica" is not "críticos"). The side analysis no longer produces a caveat with no group (it is an invalid answer); the QA function still accepts one, which then only needs the outlet, the verb and the question mark. The rule checks the form, not whether Helena evaluates the caveat.
- No attribution to a group that the pauta never cites (`problemas_das_atribuicoes`). The title, the summary, the key points and the turns may not attribute anything to an unnamed group ("para os analistas, ...", "especialistas afirmam", "segundo as análises") unless some text of the pauta (title or full text of any of its articles) has a word of the same family. The groups, the attribution markers and the verbs are closed lists in `ai/atribuicoes.py`; "para os <grupo>" only counts at the start of a clause and followed by a comma, and a group preceded by "nossos", "dois" and similar is the cast of the episode, not a source. An open question is not an attribution: a sentence that ends in "?" and has an interrogative word (o que, como, qual, quais, por que, quem, onde, quando) before the group ("O que os especialistas dizem sobre isso?"); a question that carries a statement ("Os especialistas dizem que..., não é?") still counts. The verbs after the group are the plurals of the first 21 position verbs plus a few others; the list does not follow the position verbs added later, since a new verb there would make the rule reject more.
- Numbers come from the pauta (`problemas_dos_numeros`). Every percentage, and every other number from 10 up, in digits or written out, in the title, the summary, the key points and the turns must be in some text of the pauta (title or full text of any of its articles). A percentage only matches a percentage, and a decimal said with "vírgula" is read as one number ("quarenta e dois vírgula cinco por cento" is 42,5%). Rounding follows `numeros.tem_fonte`: with "cerca de" or "aproximadamente" the number may be up to 5% away from one of the source; with "quase" the source must be below what is said and with "mais de" above it, also within 5%; with no qualifier only the integer that rounds or truncates a decimal of the source passes (12,6 may be said as 12 or 13). The same holds in the scale in which the episode says the number: said in thousands, millions or billions, it may round or truncate the source value in that scale, whatever the form the source writes it in ("245 milhões" or "246 milhões" for R$ 245,5 milhões or R$ 245.500.000), as long as the source number in that scale is 10 or more, so "3,6 bilhões" is never "três bilhões" (`Numero.escala`, `MENOR_NUMERO_NA_ESCALA`). "E meio" after milhão, bilhão or trilhão adds half the scale ("dois milhões e meio" is 2.500.000); not after mil or units ("dez e meia" is a time). A number that is part of the name of an outlet of the pauta does not count (`numeros.numeros_fora_dos_nomes`, decision of 25/10/2026: "Poder360", "Poder 360", "Brasil 247"; the name compared part by part, letters and digits apart, without accents or case, before a slogan); on the recorded episodes only the 86+71 of the preview had one, and it stays rejected for other reasons. `scripts/checar_fidelidade.py` already counted the outlet's name as part of its text. Smaller numbers stay in the diagnostic. A number written out continues across a comma right after the scale, before a part smaller than it (`numeros._continua`, decision of 29/10/2026: "nove mil, quinhentas e quarenta e quatro" is 9.544, as without the comma; a scale as large as the one before the comma, after it, means the comma separated two numbers, and the reading goes back to it: "dez mil, vinte mil" is 10.000 and 20.000; on the 236 recorded episodes since 17/10 only the C1.1 of the blind validation changes, and its two number problems go away). In an interval ("entre quinze e dezesseis bilhões", "de 3 a 5 milhões", "entre quinze e vinte por cento") the scale, or the "por cento", said on the last number holds for both, only when the first is 10 or more, the part the QA charges (`numeros._intervalos`, decision of 07/11/2026; measured on the 52 recorded reports, only the AMD episode of 04/11 changes, from rejected to approved). A decimal said with "zero", "um" or "ponto" is read too ("zero vírgula vinte e cinco" is 0,25, "um ponto setenta e dois" is 1,72; 05/11/2026). A known gap of the reading, left for the diagnostic because fixing it would make the rule reject more: "três vírgula seis bilhões" is read as 3,6, without the scale.
- The role of an analyst (`problemas_dos_papeis`). The field `papel` of a character other than Helena may not carry the name of an actor of the sides ("analista da Construtora Alfa").
- The names of the analysts (`problemas_dos_nomes`, fourth decision of 24/10/2026). The code gives them (`ai/elenco.py`, avoiding the actors and, since 25/10/2026, the people cited in the texts of the pauta) and the block of sides says them, so every analyst who speaks in the script must have one of the names the block gives (compared without accent or case, titles included: "Dr. Otávio" is not "Otávio"); the name is checked, not the side. The problem belongs to the cast, so it asks for the full revision, which may rename the analyst to the name of the block (`PROMPT_REVISOR`); the script revision keeps the names. Until the third decision the model chose the names, and the QA only refused the name or first name of an actor (the N86 called its analyst "Bruno Silva", the columnist who is the source); the sentence in the prompt that forbade it made all 12 analysts of the third short run come out with function names ("Analista de Política", "Analista Jurídico"), against none in 140 before, and it was dropped.

**Requested in the prompt only.** The model is instructed to follow these, but nothing checks them (`ai/prompt.py`):
- Use only information from the sources; do not invent data or quotes.
- Who says what (`## QUEM DIZ O QUÊ` in `PROMPT_SISTEMA`, a short version in `_REGRAS_DO_ROTEIRO`): accusation, criticism, opinion, evaluation and forecast are always attributed to whoever makes them, in the whole episode, even with a single side and no answer; a caveat of the outlet itself ("a estimativa é da associação, não de um levantamento independente") is kept, attributed to the outlet; the outlet's own analysis is attributed to the outlet, never to an actor or stated as fact; Helena, the analysts and `por_que_importa` add no evaluation, motive, consequence, forecast or argument the texts do not carry; with little material the target of the block is already smaller, and they meet it with what the texts carry, with no new argument (the "say less" of 23/10 was dropped on 24/10, since it contradicted the instruction to expand to the target); Helena builds no choices, dilemmas or contrasts the texts do not make (comparing two proposals is not putting the listener before a choice).
- Short, attention-grabbing title without sensationalism, derived from `resumo_didatico`: it states nothing the summary does not (only the absence of percentages and proportions is checked by code). The title names the actors as the sources name them, without turning a person into the institution or the state.
- 2 to 5 self-contained key points.
- "Why it matters" section with 1 to 3 sentences, with the impact the texts carry: no consequence or forecast they do not make.
- Helena is fixed as the presenter and only moderates: she asks, sums up and hands over, without taking a position.
- The plan of the turns that the block gives (see "The word budget"): how many turns each character has, of what size and in what order, starting and ending with Helena (since 24/10/2026; before, a single number of turns of 70 to 80 words for everyone, which gave Helena half of the words). Before answering, the model counts the words of each turn and expands the turns to the size of the plan, so that each character reaches its target, with what the texts carry, with no new argument (`PROMPT_SISTEMA`). Both revisions get the same block and keep the plan: they fix what the QA pointed out without shortening the turns (`_REGRAS_DO_ROTEIRO` and the two revision prompts; in the A63 and the N13 of 24/10 the revision had taken the script below the minimum).
- Helena opens, moderates and closes the episode. In the closing she recaps the facts and the positions, each attributed to whoever holds it, and says goodbye; she only speaks of what remains open when the texts say what remains open, and draws no conclusion the texts do not draw ("fica claro que...", quoted in the prompt as what not to do) (`PROMPT_SISTEMA` and `_REGRAS_DO_ROTEIRO`, second decision of 24/10: in the short run of that day, "what the texts say remains open" produced unsupported claims in 3 closings of 8). Who closes is not checked by the QA: `scripts/testar_episodio.py` records it as a diagnostic (episodes ending with an analyst: 6 of 20 on 17/10, 1 of 20 on 23/10, 2 of 8 on 24/10).
- Written to be spoken: no markdown, URLs or lists.
- Cite outlets by name.
- The question of the block is an internal guide: Helena presents it once, at the opening, in natural words, without repeating it literally and without turning the positions of the sides into questions attributed to the actors. The analysts present the positions.
- With two sides or more, each analyst answers for one side and sustains its position with the arguments of the sources: no criticism of the own position, no endorsement of the other side, no judgement of his own. He speaks in the third person ("a construtora sustenta..."), never as a spokesperson ("nós", "não podemos aceitar"), and the analyst of a thin side does not expand beyond what the sources carry (the prompts no longer give him a fixed range: his target comes from the budget). With a single side the analyst explains the position and answers the caveats with what the sources say, without advocating.
- In `personagens`, the analysts take the names the block gives (checked by code) and the role goes in `papel`, which states a speciality and no tie to an actor (the tie is checked by code).
- Helena brings each caveat as an attributed question without evaluating it, followed by an open question that does not rephrase the alert in her own words (only the form is checked by code). The code checks the form of the attribution (outlet, position verb and actor in one sentence), not whether it is faithful to the texts, nor Helena's neutrality.
- The episode neither invents a side, actor or position that the sources do not carry nor omits a side or a caveat of the block.
- With several sources, `resumo_didatico` carries the consensus. The sentence announcing the debate only appears, as an extra closing sentence, when `houve_divergencia` is true.

**Other editorial principles in the code:**
- "Boletim duplo": feeds are interleaved so `MAX_NEWS` is not consumed by the first feeds alone, since TechDigest and PulsoBR share each batch (`collectors/rss.py`).
- No sport, offers or party sites (`processing/filtro.py`, owner's decisions of 16, 17 and 25/10/2026), with the grouping on or off. Sport and offers go by the first segment of the URL path (`/esporte/`, `/esportes/`; `/achados/`, `/hardware-indica/`, `/ofertas/`), by whole sport sites (ge.globo.com, lance.com.br, goal.com, cbf.com.br) and by the feed category, a closed list compared without accents or case (Esporte, Esportes, Ofertas, Achados, Hardware Indica); never by the title. Party sites go by the list of domains in `config/sites_de_partido.txt` (one per line, each also covering its subdomains; a line that is not a domain is an error), checked on the final URL. The list, approved by the owner on 25/10/2026, has the 30 parties registered with the TSE, each domain checked by hand (`data/agrupamento/filtro_20261025/sites_de_partido_conferencia.md`; pcb.org.br and pv.org.br stay although their content could not be checked); the sites of party leaderships, foundations and federations stay out until one shows up in the record of a run. Measured on the two first samples: the same result as the measure of 16/10 (sport 12 of 12, offers 16 of 21, the party site 1 of 1, no false positive). A filtered item is not marked as seen, like a short text: it comes back and is filtered again.
- An item rejected by the QA in `MAX_REPROVACOES` (2) runs is abandoned (owner's decision of 16/10/2026): only `QAReprovado` counts, never a network or Ollama error. The count is in the table `reprovacoes` of `data/digest.db` (`SeenStore.registrar_reprovacao`), an additive change: `seen` keeps meaning "delivered", and the `master` reads and writes `seen` as before, ignoring the new table (if the code went back to the pre-merge `master`, it would try those items again).

## Architecture

`main.main()` reads the arguments (before importing anything that reads the configuration, see the simulation), sets up logging and calls `pipeline.run()`, which takes the model lock and then loops over the articles (with `AGRUPAMENTO_ATIVO`, over the pautas; see below) in `pipeline._executar()`. The model lock (`trava.py`) is a non-blocking exclusive `flock` on a fixed path outside both project folders, `~/.local/state/techdigest/modelo.lock` (next to the Ollama log, never from `.env`, so the main folder, a worktree and a simulation share it), taken by everything that calls the model: the pipeline, the simulation, `testar_episodio.py` and `testar_agrupamento.py --etapa3`. The holder writes its command, PID, start time and folder in the file; a run that finds it busy logs `Execução não começou: ...` with that text and exits with status 1. Before the loop, `_executar()` wraps the provider in the machine brakes (`ai/maquina.ProviderVigiado`) and checks the GPU, before collecting anything:

1. `collectors/rss.collect_rss()` downloads each feed, filters by age (`MAX_IDADE_DIAS`) before applying `MAX_POR_FEED`, and **interleaves** the feeds so `MAX_NEWS` is not consumed by the first feeds only. Each `Article` keeps the URL of its feed (`feed`, the first one in the interleaved order when a link is in two feeds) and the categories of its entry (`categorias`), for the filter of phase 4. A feed that fails with a network error (connection, timeout, 408/429/5xx) is retried in rounds after the others (`FEED_TENTATIVAS` attempts in all, 4 by default, waiting `FEED_ESPERA_S` seconds, 20 by default, and double each round: 20, 40, 80), because after the machine wakes the network may take a minute and the failure hits feeds of several hosts at once; a recovered feed keeps its place in the interleaving, and a 404 or a feed with no entries is not retried. `collect_rss(coleta=ColetaRSS())` fills which feeds stayed out and which recovered; the record keeps them in `feeds` and, with some feed out after the attempts, `pipeline._coletar` sends a short plain-text notice through the stop-notice path (`Aviso de feeds: ...` in the log) and the run goes on; with every feed out it stops with the stop notice and status 1 (`ExecucaoInterrompida`).
2. `storage/dedup.SeenStore` (SQLite table `seen`, keyed by SHA-256 of the URL) skips items already delivered, and its table `reprovacoes` skips the items the QA rejected in `MAX_REPROVACOES` runs (see the editorial principles). The filter of `processing/filtro.py` then drops sport, offers and party sites by the feed link and the feed category, before any extraction, logging `Item filtrado (<reason>): ...`.
3. `processing/extractor.extrair()` fetches the article body with trafilatura and returns it with the resolved URL (the same text `extract_full_text()` gives); the filter runs again on the resolved URL, since a Google News link only shows the site once resolved (`Item filtrado (<reason>, depois da extração): ...`). Google News links are first resolved to the publisher URL with `googlenewsdecoder`; trafilatura is never run against a google.com URL (it would return the cookie-consent page). Items with less than `MIN_TEXTO_CHARS` of text are discarded.
4. `ai/summarizer.Summarizer.process()` asks the LLM for the question in dispute and the sides of the pauta, on the whole texts (`ai/lados.py`, one call with `PROMPT_LADOS`, repeated once if the answer is not valid or lacks the entry of an actor), cuts each text by relevance to a size budget (see below), calls the provider with `PROMPT_SISTEMA` and the input that carries the sides, runs the deterministic checks in `ai/qa.py`, and on failure makes **one** correction, of the kind the problems ask for (see "The corrections" below; only the title correction may take a second call). If the corrected episode still fails it raises `QAReprovado`. Every item therefore costs two LLM calls, plus one when the side analysis has to be retried and one or two with a correction (two when the title correction is repeated): five in the worst case, and up to eight since 30/10/2026, when each call of the generation and of the corrections may be repeated once for an incomplete JSON (`Summarizer._chamar_inteiro`): two of side analysis, two of generation and four of title.
5. `audio/tts.atribuir_vozes()` gives each character a voice (Helena the fixed one, each analyst the voice of the slot of his name), which goes to the log (`Vozes: Helena → ...`) and to the episode (`vozes`), and `audio/tts.gerar_podcast()` synthesizes one mp3 per dialogue turn, inserts silences with ffmpeg and concatenates into `data/audio/<slug>.mp3`.
6. `delivery.deliver_item()` sends the text and then the audio to Telegram, and only after that does the pipeline call `seen.marcar_vistos()` (the article, or with the grouping on the whole pauta, in one transaction). A `QAReprovado` adds one to the item's count in `reprovacoes`; at `MAX_REPROVACOES` the item is abandoned (`Item abandonado (reprovado pelo QA em N execuções): ...`).
7. Every run writes its record (`registro.py`) in `EXECUCOES_DIR/<date-time>/` (`data/execucoes/` by default): `amostra.json` with the articles that reached the generation and their full texts, `relatorio_<date-time>.json` with each item (situation, side analysis, cut, word budget, QA problems, correction, the names of the block, the voices, whether it was delivered and the episode file), the filtered and the abandoned items, and one JSON per episode, approved or not. It is the format of `scripts/testar_episodio.py`, so `scripts/checar_fidelidade.py --relatorio <file>` and `scripts/refazer_qa.py <folder>` read it as they are; the functions that build its parts are the same in both (`registro.lados_para_registro`, `cortes_para_registro`, `orcamento_para_registro`). The report is rewritten after every item, a failure to write it never stops the run, and folders older than `EXECUCOES_DIAS` (30) days are deleted at the start of each run (30 days approved by the owner on 25/10/2026; 0 keeps them all).

With `AGRUPAMENTO_ATIVO=true` (off by default; owner's decisions of 16, 17 and 25/10/2026) steps 2 to 6 work by pauta (`pipeline._pautas_da_execucao`, adjustment 7 of 17/10/2026). The run drops the delivered, the abandoned and the filtered articles (by the feed link and category), extracts every remaining candidate at once (`extractor.extrair_em_lote`, about a minute for a hundred), applies the filter to the resolved URL, drops the short texts and groups them (`pipeline._agrupar`): stages 1 and 2 form provisional pautas of up to `AGRUP_MAX_PROVISORIA` (6) articles, and stage 3 (`agrupamento.confirmar_pauta`, one call per provisional pauta of two articles or more, through the machine brakes, logged as `Etapa 3: pauta provisória de N artigos → ...`) confirms each; what it confirms beyond `AGRUP_MAX_ARTIGOS` (3) texts becomes `excedentes`. A stage-3 call that fails, or a verdict that is discarded, leaves the articles apart, and an unexpected error in the grouping leaves every candidate on its own (`Agrupamento falhou: ...`), so the run goes on. Each pauta takes the slot of the first of its articles in the interleaved list (principal, related, duplicates and excess counted), so the double bulletin still holds and a pauta of several feeds takes one slot; the pautas are generated in that order until `MAX_NEWS` episodes are delivered or the time budget ends, and what does not fit is not marked and comes back, maybe with new articles. The principal and the related articles go to `Summarizer.process(principal, relacionados)` (`Pauta de N textos (...)` in the log). The delivered text has a link for each generated article (the feed's) and lists the duplicates and the excess articles under "Também noticiaram" (`_render_item`; with a single source it is the text of before); after delivery every link of the pauta, generated, duplicates and excess, is marked as seen in one transaction (`SeenStore.marcar_vistos`); a `QAReprovado` counts for the generated articles and the duplicates, not for the excess ones. The same story through two feed links (Google News and the outlet's feed) is a duplicate when both resolve to the same canonical URL (`agrupamento._mesma_materia`), even with different extracted texts. The record of the run also keeps each provisional pauta and what stage 3 did with it (`etapa3`) and, per item, its `duplicatas` and `excedentes`. With the grouping off none of this runs: the loop takes one article at a time, as before; the only difference is the date of each article in the record, since the collection now fills `Article.published` from the feed (stage 3 shows it to the model).

Invariants worth preserving:

- **Deliver first, mark seen after.** An interrupted run neither loses nor repeats a delivered item, and anything not delivered comes back on the next run. This includes QA rejections (retried next run) and the case where the text was sent but the audio upload failed (`AudioNaoEnviado`): the item is not marked seen, so the next run sends it again in full.
- **One bad item never kills the run.** Generation errors are caught per item and logged. Only `MAX_FALHAS_ENTREGA` consecutive delivery failures abort the run, by raising, which makes `main` exit with status 1 for systemd.
- **A machine brake stops the whole run.** Memory, temperature and GPU belong to the machine, not to an item. `ai/maquina.ProviderVigiado` checks before every call the CPU temperature (above `MAX_CPU`, 95 °C, it waits until below `RETOMAR_CPU`, 85 °C, for at most 15 minutes) and the available memory (`MIN_MEMORIA_GIB`, 4 GiB); with the local model also the GPU before the first call and after the load (`ai/gpu.py`, on `OLLAMA_LOG`; also after a call that failed with the model loaded) and whether Ollama still answers with the model loaded. A brake raises `ExecucaoInterrompida`, a subclass of `SystemExit`, so the per-item `except Exception`, the retry of the side analysis and the per-pauta handlers of the scripts let it through; the pipeline logs `Execução interrompida: <reason> (N notícia(s) entregue(s) antes; ...)` and `main` exits with status 1. What was not delivered stays for the next run.
- **The process tells the owner when it stops** (adjustment 8 of 17/10/2026 and the owner's decision of 25/10/2026). When the run does not start because the model lock is busy, stops at a machine brake, or ends with an unexpected error (any other exception, the consecutive delivery failures included), `pipeline.run` logs `Aviso de parada: <text>` and sends the text through `delivery.deliver_aviso` before exiting with status 1: in production a plain message in the Telegram chat, through the same `_post` that hides the token; in a simulation `<folder>/AVISO.txt` and stderr, never Telegram. The text says the time, the reason (for an unexpected error only the type of the exception; the traceback stays in the log) and how many items were delivered out of `MAX_NEWS`. If the notice itself fails, the log gets `Aviso de parada não enviado (...)` and the exit is the same. What the process cannot notice (the OOM killer, the 4-hour limit, a signal) is for the `OnFailure=` of the future unit.
- **Time budget.** No new item starts after `MAX_RUNTIME_MIN`; the systemd unit kills the process at 4 hours.
- **No call is cut silently.** Every request to Ollama goes with `truncate` and `shift` off (see "The input budget"): an input over the window is an error that is redone once with a smaller input, never a prompt cut in the middle, and an answer that reaches the end of the window is an error, never a shifted context. Keep it when adding a call.
- **The Telegram token must not reach the logs.** The token is part of the request URL and `requests` errors quote the URL, so `delivery/telegram._post` re-raises with `from None` and without the URL.

### The input budget

`summarizer.montar_entrada()` keeps the message of each call inside a character limit, so the provider never has to truncate it, and no request to Ollama is cut silently (`truncate` and `shift` off). The whole section (the share of each part, the cut by relevance, the limit from the window, the fixed part, the proportion of the text, `JanelaExcedida`, and why the side analysis does not share this budget) is in `docs/referencia/orcamento-de-entrada.md`. Read it before changing the input of `ai/summarizer.py`, `ai/recorte.py`, the options of the calls in `ai/llm.py` or anything about the window.

### The side analysis

Before the generation, the LLM gives the question in dispute within the story and its sides: a side is one answer to that question held by named actors, and a position held only by unnamed groups is a caveat (`ressalva`). `ai/lados.py` validates the answer (the answers per actor with their excerpts, where since 04/11/2026 a direct quote counts only when it answers the question; the thin sides; the new attempt, which since 04/11 stays whenever it is valid; "Sim" and "Não") and builds the block `LADOS DA PAUTA` that the generation receives. The whole section is in `docs/referencia/analise-de-lados.md`. Read it before changing `ai/lados.py`, `ai/verbos.py`, the excerpts of `ai/recorte.py`, the analysts rule of `ai/qa.py` or the prompts of the side analysis.

### The corrections

Every problem found by `qa.problemas_com_campo()` is a `Problema` with the field of the episode it belongs to, and `summarizer.tipo_de_correcao()` picks the single correction the episode gets from those fields:

- **Title** (`"titulo"`): every problem is in the title. A short call with `PROMPT_TITULO` rewrites only the title from the summary. It receives the summary, the actors of the sides and the titles already refused, each with its reasons, no source text, and answers `{"titulo_reescrito": "..."}`. It is the only correction that may be repeated: if the new title still fails, a second call carries both refused titles (`TENTATIVAS_DO_TITULO`), because the model tends to swap one proportion for another ("maioria" for "70 dos 120").
- **Summary** (`"resumo"`): every problem is in `resumo_didatico`. A short call with `PROMPT_RESUMO` rewrites only the summary. It receives the same excerpts that went to generation (`Entrada.artigos`), whether there is a divergence, the problems and the original summary, and answers `{"resumo_didatico": "..."}`.
- **Script** (`"roteiro"`): every problem is in `roteiro_podcast` (words per character or in total, the match between analysts and sides, caveats, attributions and numbers inside a turn) or in the role of a character. A call with `PROMPT_ROTEIRO` receives the sources, the block of sides, the characters, the problems and the original script, and answers `{"personagens": [...], "roteiro_podcast": [...]}`. From the characters it returns, the code only takes the role of each name that already existed (`_com_os_papeis`): names and order never change.
- **Full revision** (`"completa"`): problems in more than one field, or in a field with no correction of its own (number of analysts, `houve_divergencia`, `fontes_citadas`, key points, malformed JSON). `PROMPT_REVISOR` receives the sources, the problems and the whole episode, and answers the whole episode.

The answer of a targeted correction is merged into the first version, and the QA runs again on the result. `Summarizer.ultimo_diagnostico` keeps the first version, the kind of correction (`correcao`), the input it used (`revisao`), the refused titles (`titulos_reprovados`) and the last whole episode (`episodio`). The rules about Helena, the analysts and the caveats are written once for the two revisions, in `_REGRAS_DO_ROTEIRO` (`ai/prompt.py`).

### The LLM output contract

The episode is a JSON object with 8 keys (`titulo_reescrito`, `resumo_didatico`, `pontos_chave`, `por_que_importa`, `personagens`, `roteiro_podcast`, `houve_divergencia`, `fontes_citadas`). That shape is repeated in `ai/llm.py` (`SCHEMA`, `REQUIRED_KEYS`), in the prose of `ai/prompt.py` and in the consumers (`ai/qa.py`, `audio/tts.py`, `_render_item` in `delivery/telegram.py`), which must change together. The grouping verdict of stage 3 has a second, smaller contract (`PROMPT_AGRUPADOR`). Both contracts and `parse_json`/`chat_json` are detailed in `docs/referencia/contrato-de-saida.md`; read it before changing any of those places.

The examples in the prompts (questions, actors, outlets, roles, proportions) are invented and come from none of the samples in `data/agrupamento/`: when the side analysis had "O canal deve ser suspenso?" as its example question, the model gave that same question to two pautas of the same story, the right one by coincidence and the wrong one. Keep any new example away from the content of the samples (grep each name in all of them), and use no outlet that exists: in a prompt about attribution, a real outlet is a name the model may put in an episode where it is not a source. On 23/10/2026 "Jornal do Vale" and "Diário do Litoral", which exist, were replaced in `PROMPT_SISTEMA` by invented ones (`tests/test_summarizer.py` checks that they stay out); the tests and this file still use them, since the model never reads those.

The presenter name `Helena` is fixed by the prompt and mapped to a fixed voice in `tts.VOZ_FIXA`. The analysts' names come from `ai/elenco.py`, by slot (the slot i is the analyst of side i; with one side, the first): in each slot the first name that is neither the name nor the first name of an actor of the analysis (`elenco.mesmo_nome`). The names barely appear in the phase 4 samples, so they rarely coincide with a person cited who is not an actor. Each slot has its voice, of the gender of its names (`tts.VOZES_DIVERSIDADE`, same position: Antonio, Thalita, Gustavo), and `tts.atribuir_vozes` gives each listed name the voice of its slot; any other name gets, in declaration order, a voice left over. Until 24/10 every analyst got a voice by declaration order, so a single female analyst spoke with the first, male, voice.

### The word budget

The number of words of the script follows the material the generation receives (`ai/orcamento.py`): the targets of the total and of each character, Helena's share and the plan of the turns go to the block of the generation, to both revisions and to the QA, and the prompts no longer hard-code word, turn or thin-side numbers. The whole section is in `docs/referencia/orcamento-de-palavras.md`. Read it before changing `ai/orcamento.py`, the word rules of `ai/qa.py` or the block of the generation.

### Logging and the log-summary script

`logging_setup.py` configures the `techdigest` logger once: console at `LOG_LEVEL`, plus `data/logs/techdigest.log` always at DEBUG (rotating, 2 MB x 7). Modules log through `logging.getLogger("techdigest.<module>")`.

`scripts/resumo_lotes.py` parses that file with regexes over the line format and over exact message texts (`=== TechDigest iniciando ===`, `Execução concluída: N notícia`, `Item pulado pelo QA`, `Item descartado`, `Falha ao entregar`, `Execução interrompida:` (a machine brake, shown in the table with its reason), `Execução não começou:` (the model lock was busy, listed after the table), `Item filtrado` and `Item abandonado` (columns of their own), `Aviso de parada:` and `Aviso de parada não enviado` (in the notes), `Agrupamento: N candidato(s) em M pauta(s), K com várias fontes`, `Agrupamento falhou`, the count of `Janela: o texto de` (single-source texts cut by the window) and of `Janela: ... passou da janela` (calls redone) (in the notes), and the Ollama metrics line with `tok/s`, `RAM disp.=`, `CPU=`, `GPU=`). Rewording those messages or changing the format string breaks the script silently. The metrics line is logged once per LLM call, so its averages now include the short side-analysis call of every item.
