# The LLM output contract

> Moved out of `CLAUDE.md` on 04/11/2026, verbatim, so that the context every session and worker loads stays small. `CLAUDE.md` keeps a short summary under the same heading; when this file changes in a way that makes that summary wrong, fix the summary too.

The episode is a JSON object with 8 keys (`titulo_reescrito`, `resumo_didatico`, `pontos_chave`, `por_que_importa`, `personagens`, `roteiro_podcast`, `houve_divergencia`, `fontes_citadas`). That shape is repeated in several places that must change together:

- `SCHEMA` / `REQUIRED_KEYS` in `ai/llm.py`. The schema is not sent to the provider (Ollama gets `format="json"`, OpenAI gets `json_object`); only the presence of the required keys is enforced, in `parse_json`, which raises `JSONIncompleto` (a `ValueError`) when a key is missing. The generation and the four corrections call the model through `Summarizer._chamar_inteiro`, which repeats the same call once on `JSONIncompleto` (decision of 30/10/2026: the C3.48 of the regression of 29/10 closed the JSON right after the summary); the repetition is not a QA rejection and does not count for the attempt limit of the item, and if the second answer is incomplete too, the error goes on as before (a failed generation, or a correction that failed). Broken JSON is not repeated, because with Ollama it does not come from the model's choice: the calls go with `format="json"`, so the server only lets valid JSON out, and an answer cut at the window or at `num_predict` stops with `done_reason` "length", which `OllamaProvider.chat_json` raises as a truncated output before `parse_json`; the same call, with the same input and the same limits, would be cut at the same point, and the fix for that is in the input budget. A valid JSON that closes before all the keys is the model's choice, sampled at the provider's temperature (`OLLAMA_TEMPERATURE`, 0.5 by default), so the same call can come whole the second time. The OpenAI path already repeats an unusable JSON inside `OpenAIProvider.chat_json`, and after its own attempts it raises a plain `ValueError`, not `JSONIncompleto`: there the Summarizer does not repeat the call again. In the production log of 05 to 26/10 no answer came as broken JSON. `Summarizer.json_incompleto_refeito` and the `json_incompleto_refeito` of the diagnostic count the calls repeated in the item, and the record of each run (`registro.py`) and the report of `testar_episodio.py` keep the count per item. In the production log of 05 to 26/10 (382 items) no answer came incomplete; in the recorded rounds, only the C3.48.
- The prose in `ai/prompt.py` (`PROMPT_SISTEMA` and `PROMPT_REVISOR`) and the reminder (`LEMBRETE`) appended by `summarizer.montar_entrada`. `PROMPT_TITULO`, `PROMPT_RESUMO` and `PROMPT_ROTEIRO` each ask for one or two of those keys alone, and the revision of the script closes its input with `LEMBRETE_DO_ROTEIRO`.
- The consumers: `ai/qa.py`, `audio/tts.py` and `_render_item` in `delivery/telegram.py`.

There is a second, much smaller contract: the grouping verdict (stage 3 of the news grouping, see "Unfinished or dormant code" in `CLAUDE.md`). The model receives one provisional pauta, with its articles numbered from 1, and answers with a JSON object whose required keys are `tipos`, `grupos` and `isolados`:

```json
{"tipos": {"1": "fato_unico", "2": "fato_unico", "3": "varios_fatos"}, "grupos": [{"principal": 1, "membros": [{"id": 2, "relacao": "mesmo_acontecimento"}]}], "isolados": [3], "motivo": "one sentence"}
```

`tipos` classifies every article first: `varios_fatos` is a text that covers several unrelated events (agenda, weekly roundup, bulletin, live coverage) and can never be part of a group. `membros` lists the other articles of the group (never the principal), `relacao` is `mesmo_acontecimento` or `desdobramento`, and every number must appear exactly once between `grupos` and `isolados`. A missing or invalid type, id or relation discards the whole verdict and leaves every article on its own. From a valid verdict the code takes who stays together, the types and how the articles relate: an article typed `varios_fatos` is removed from its group even if the model grouped it, and the model's choice of `principal` is ignored. Its pieces must also change together:

- The prose in `PROMPT_AGRUPADOR` (`ai/prompt.py`).
- `CHAVES_AGRUPADOR`, `TIPOS`, `RELACOES`, `entrada_agrupador()` (the text the model receives), `problemas_do_veredito()` and `compor_pautas()` in `processing/agrupamento.py`.

`parse_json(text, chaves)` and `chat_json(system, user, chaves=, temperatura=, max_saida=)` take the required keys and the sampling options per call. With no extra arguments a call is the episode call: `REQUIRED_KEYS` and the values from `.env`. `num_ctx` is never set per call, because changing it makes Ollama reload the model.
